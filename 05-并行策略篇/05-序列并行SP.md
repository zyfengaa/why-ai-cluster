# Q: 长序列训练为什么需要序列并行（SP）？

## 为什么会有这个问题

当序列长度从 4K 增加到 128K 甚至 1M 时，attention 相关的显存会**随序列长度二次增长**。先把公式写对——attention 的分数矩阵是每个 head 一张 S×S 的表：

```
逻辑 attention 矩阵显存 ≈ B × n_heads × S² × bytes（等价量级 B × S² × hidden × bytes / head_dim）
```

按明确假设重算（B=1、FP16）：

```
seq_len = 131072（128K），n_heads = 32：
  1 × 32 × 131072² × 2 字节 ≈ 1.1 TB（单层！）

seq_len = 131072，n_heads = 64（无 GQA 的 64 头配置）：
  ≈ 2.2 TB

seq_len = 32768（32K），n_heads = 32：
  ≈ 68 GB（单层，已接近单卡极限）
```

**两个必须区分的概念**：

1. **逻辑 attention 矩阵**（上面的 S×S 分数表）：数学上存在，但**现代实现根本不物化它**——
2. **实际物化激活**：用 FlashAttention 后，每层激活从 O(S²) 降到 **O(S×H)**（每层约 34×S×H×2 字节的量级；128K、H=4096 时约 36 GB/层）。

所以"128K 序列单层 2TB"说的是**如果不做任何优化、把 S² 矩阵完整物化**的量级；FlashAttention 把它压掉一个数量级以上，但 O(S×H) 的激活在 80 层、多卡分摊后依然紧张——这才是长序列训练真正的工程问题。

## 解决什么问题：序列并行（Sequence Parallelism，SP）

**先划清 SP 与 CP 的边界**（这是最容易混淆的地方）：

| 方案 | 切什么 | 通信模式 | 适用序列长度 | 代表实现 |
|------|--------|---------|-------------|---------|
| **Megatron-SP** | LayerNorm / Dropout / 残差等按序列维的激活区域（配合 TP 的通信重排）；**不切 attention 的 S² 计算** | 与 TP 的 All-Reduce/All-Gather 重排为 Reduce-Scatter/All-Gather | ≤ 128K | Megatron-Core |
| **DeepSpeed-Ulysses** | 按 head 维划分 Q/K/V，all-to-all 聚合注意力输入 | All-to-All | ≥ 128K（要求 head 数 ≥ 并行度） | DeepSpeed |
| **Ring Attention（CP）** | **真正切 attention 的序列计算**：Q/K/V 按序列分块，KV 在环上滚动传递 | 环上 P2P | 128K – 1M+ | Megatron CP / Ring Attention (arXiv:2310.01889) |

### Megatron-SP 实际做什么

```
一个 Transformer 层（TP=2 时）：
  [All-Reduce]  →  residual + LayerNorm + Dropout  →  [Attention（完整计算）]  →  [All-Reduce]  →  residual + LayerNorm + Dropout  →  [MLP]

Megatron-SP 的做法：
  两个 All-Reduce 各替换成 Reduce-Scatter + All-Gather 的组合，
  于是夹在中间的 LayerNorm / Dropout / 残差区域
  天然以序列分片的形式存在（每卡只过 S/SP 段）。

  Attention 本身的 Q×K^T→Softmax→×V（S² 计算）没有被切——
  每卡仍然对完整序列做 attention。
```

**要切 attention 的 S² 计算本身，用的是 CP（Context Parallelism）**：Ring Attention 把序列分块、KV 在环上滚动，每卡只对自己那段 Q 做完整注意力；Ulysses 按 head 维切分后 all-to-all。这是 SP 和 CP 的分界线。

### 显存到底被谁分片（别再写"÷ (TP×PP×DP×SP)"）

```
参数 + 梯度 + 优化器状态：被 TP 分片（若再叠 ZeRO/FSDP、EP 则进一步分片）
  —— DP 不参与：DP 是模型状态的完整复制，每张 DP 卡都要有整套
激活：
  ├─ TP 分片的部分（attention/MLP 内部）
  ├─ SP 分片的部分（LayerNorm/Dropout/残差区域，Megatron-SP）
  └─ attention 部分：FlashAttention 压到 O(S×H)；要按序列再切，靠 CP
```

## 优缺点

| 优点 | 缺点 |
|------|------|
| ✅ **降低部分激活显存**：LayerNorm/Dropout 等区域随 SP 线性下降 | ❌ **通信通常增加**：All-Reduce 变为 Reduce-Scatter + All-Gather，总线上流量并不减少 |
| ✅ **与 TP 天然融合**：通信重排后共用同一组原语（Megatron-SP 的设计精妙之处） | ❌ **不解决 attention 的 S² 问题**：那是 FlashAttention 和 CP 的事 |
| ✅ **支持超长上下文**：CP（Ring/Ulysses）可到 1M+ | ❌ **Ring Attention 实现复杂**：KV 环传与负载均衡需要框架支持 |
| ✅ **Ulysses 与 ZeRO-3 兼容** | ❌ **SP degree 受序列长度限制**：序列太短时切分没有意义 |

---

## 2026 年的实际应用

| 场景 | 序列长度 | 推荐方案 | 显存效果 |
|------|---------|---------|---------|
| 标准训练 | 4K - 8K | 不需要 SP/CP | — |
| 中等上下文 | 32K - 64K | FlashAttention + Megatron-SP | 部分激活 ÷ SP |
| 长上下文 | 128K | Megatron-SP + CP | attention 激活 ÷ CP |
| 超长上下文 | 1M+ | CP（Ring Attention）+ FlashAttention 3 | 每卡只算 S/CP 段 |

**2026 年趋势**：长上下文已成为标配。GPT-4 支持 128K，Claude 支持 200K，Gemini 2.5 支持 1M 以上。**长上下文训练的主力是 FlashAttention + CP；Megatron-SP 是配合 TP 的补充手段，不是显存问题的万能解。**

## 🛠 实操指南

### 📋 决策指南：你的场景需要什么？

```
当前序列长度是多少？
├─ < 16K → 不需要，3D 并行 + FlashAttention 就够
├─ 16K - 64K → FlashAttention 必开；激活仍紧张时上 Megatron-SP（挂在 TP 组上）
├─ 64K - 256K → + CP=4/8（Ring/Ulysses，真正切 attention）
└─ > 256K → CP（Ring Attention）为主，可能叠加多层 CP
```

**显存快速判断公式**：

```python
# ① 逻辑 attention 矩阵（若完整物化 softmax 分数——仅用于理解量级）
seq_len, n_heads, batch_size, bytes_per = 131072, 32, 1, 2
logical = batch_size * n_heads * seq_len**2 * bytes_per
print(f"逻辑 attention 矩阵: {logical/1e12:.2f} TB / 层")
# → 1.10 TB / 层（128K、32 heads、FP16、B=1）

# ② FlashAttention 下每层实际物化激活（量级估算，O(S×H)）
hidden = 4096
per_layer = 34 * seq_len * hidden * bytes_per     # 系数 34 为经验量级（含 QKV/O/MLP 中间量）
print(f"FlashAttention 每层激活: {per_layer/1e9:.1f} GB / 层")
# → ≈ 36 GB / 层

# ③ Megatron-SP=8 只切其中的序列分片区域（LayerNorm/Dropout/残差等）
sp = 8
f = 0.15                                          # 可按序列切分区域的占比（示意值）
with_sp = per_layer * (1 - f) + per_layer * f / sp
print(f"Megatron-SP=8 后: ~{with_sp/1e9:.0f} GB / 层 量级")
# → ~32 GB / 层：只省了序列分片区域，attention 主体没动

# ④ 要把 ① 的 1.1 TB 除以 8，必须用 CP（Ring/Ulysses）→ 137 GB/卡·层
#    继续加 CP 度或配合 FlashAttention 分块流式计算才行
```

### ⚠️ 常见误区

- **误区**："SP 把 attention 显存除以 SP，显存随 SP 线性下降"
  - **实际**：Megatron-SP **不切 attention 的 S² 计算**，只切 LayerNorm/Dropout/残差等区域——这部分省了，attention 主体没动。真正把 attention 计算和激活按序列切分的是 **CP**（Ring Attention / Ulysses）。把两者混为一谈是 SP 文章里最常见的事实错误。

- **误区**："SP 是纯显存优化，不影响计算速度，通信还更低"
  - **实际**：Megatron-SP 把 TP 的 All-Reduce 重排为 Reduce-Scatter + All-Gather，**通信量通常持平或略增**，不是"通信更低"。CP 则额外引入 KV 环传（Ring）或 all-to-all（Ulysses）。它们的收益是"能训更长序列"，代价是通信。

- **误区**："开了 SP，attention 就从 O(N²) 降到 O((N/SP)²)"
  - **实际**：单卡 attention **计算量**的下降只发生在 CP（每卡只算 S/CP 段的 Q）。Megatron-SP 下每卡仍对完整序列做 attention。计算复杂度的降低、以及"逻辑矩阵"与"实际物化激活"的区别，要分开表述。

- **误区**："SP 和 TP 是一样的，切分方式不同而已"
  - **实际**：TP 切的是 **hidden_dim**（矩阵的列/行），SP 切的是**激活的序列维区域**。Megatron-SP 的实现正是把 TP 的通信原语重排（All-Reduce → Reduce-Scatter + All-Gather），使 LayerNorm/Dropout 区域天然按序列分片。

### 📊 底线数字速查

| 指标 | 优秀 | 及格 | 报警 |
|------|------|------|------|
| 序列长度 | < 16K（不需要 SP/CP） | 16K-128K（SP+CP） | > 128K（必须 CP） |
| 逻辑 attention 矩阵（128K、32 heads、FP16） | FlashAttention 不物化 | CP 分块 | 完整物化（1.1 TB/层） |
| 每层物化激活（FlashAttention，128K、H=4096） | ~36 GB + 选择性重算 | 无重算直接存 | 物化 S² 矩阵 |
| SP/CP 通信开销增量 | < 10% | 10-20% | > 20% |
| seq_len / CP degree | > 8K | 2K-8K | < 2K |

### 💡 一句话记住

> **"长序列的显存压力分两层：逻辑 attention 矩阵是 O(S²)（128K、32 heads 就是 1.1 TB/层，但 FlashAttention 根本不物化它），实际激活是 O(S×H)。Megatron-SP 只切 LayerNorm/Dropout 区域、不切 attention；真正把 attention 按序列切开的是 CP（Ring Attention / Ulysses）。别再写'显存 ÷ (TP×PP×DP×SP)'——DP 复制模型状态，不参与除法。"**

## 对后续的铺垫

SP/CP 解决了长序列训练的显存问题。还有一种并行策略针对的是**模型结构本身**的稀疏性——MoE（混合专家模型）中，每个 token 只激活一部分参数，常规的 TP/DP 无法高效处理这种"不均匀"的计算模式。
