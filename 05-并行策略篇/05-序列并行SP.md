# Q: 长序列训练为什么需要序列并行（SP）？

## 为什么会有这个问题

当序列长度从 4K 增加到 128K 甚至 1M 时，**Attention 层的显存消耗随序列长度二次增长**：

```
Attention 显存 ≈ O(batch_size × seq_len² × hidden_dim × precision)
 
seq_len=4K:   ~2 GB（单层，容易承受）
seq_len=32K:  ~128 GB（单层，已经接近 H100 总显存）
seq_len=128K: ~2 TB（单层，远超单卡极限）
```

**核心矛盾**：标准 TP/PP 把模型参数切分到多卡，但 Attention 的**中间激活值**随序列长度二次增长，而且这些激活值需要在反向传播时保留——**当序列长度超过 32K 时，单卡存不下这些激活值。**

## 解决什么问题：序列并行（Sequence Parallelism，SP）

SP 的核心思想：**把序列维度也切分到多张 GPU 上，每张 GPU 只处理序列的一个片段。**

### 两种主流方案

| 方案 | 组织 | 核心思路 | 适用场景 |
|------|------|---------|---------|
| **Megatron-SP** | NVIDIA | 把 LayerNorm + Dropout 在序列维度切分，Attention 保持完整（更简单的通信模式） | ≤128K 序列 |
| **DeepSpeed-Ulysses** | Microsoft | 把 Attention 的计算分布到多卡，每卡算序列的"子注意力"（更灵活的切分） | ≥128K 序列，结合 ZeRO-3 |
| **Ring Attention** | 学术界 | 所有 GPU 组成环，在环上"滚动"计算 attention slice | 极端长序列（1M+）|

### Megatron-SP 的工作原理

```
标准 Attention（单卡）：
Q × K^T → Softmax → Attention Score × V
（Q、K、V 都是 [seq_len × hidden_dim] 的形状）

SP 切分（假设 SP=2）：
GPU 0: Q[0:seq_len/2] × K^T[0:seq_len/2] → 前半部分的 Attention
GPU 1: Q[seq_len/2:seq_len] × K^T[seq_len/2:seq_len] → 后半部分的 Attention

然后 All-Reduce 合并结果
```

### 为什么 SP 和 TP 是互补的

```
标准 3D 并行把模型参数切分到多卡（TP/PP），但序列依然完整。
SP 再在序列维度上切一刀：

4D 并行：
TP（切 hidden_dim）+ PP（切 layers）+ DP（切 batch）+ SP（切 seq_len）

→ 每张 GPU 持有的显存 = 总显存 ÷ (TP × PP × DP × SP)
```

---

## 优缺点

| 优点 | 缺点 |
|------|------|
| ✅ **解决长序列的显存爆炸**：显存随 seq_len 线性扩展而不是二次 | ❌ **增加通信开销**：每层多一次 All-Reduce |
| ✅ **和 TP 天然的互补**：TP 切 hidden_dim，SP 切 seq_len，同一个 All-Reduce 可以合并 | ❌ **实现复杂度高**：需要精确控制切分边界 |
| ✅ **支持超长上下文**：Megatron-SP 支持 128K，Ring Attention 支持 1M+ | ❌ **Ring Attention 实现复杂**：生产和框架集成还在早期 |
| ✅ **DeepSpeed-Ulysses 与 ZeRO-3 兼容**：可以同时做序列并行的通信压缩 | ❌ **SP degree 受序列长度限制**：序列太短时切分没有意义 |

## 2026 年的实际应用

| 场景 | 序列长度 | 推荐方案 | 显存节省 |
|------|---------|---------|---------|
| 标准训练 | 4K - 8K | 不需要 SP | — |
| 中等上下文 | 32K - 64K | Megatron-SP（SP=4 或 8） | ~4-8× |
| 长上下文 | 128K | Megatron-SP 或 DeepSpeed-Ulysses | ~8-16× |
| 超长上下文 | 1M+ | Ring Attention + Flash Attention 3 | ~40×+ |

**2026 年趋势**：长上下文已成为标配。GPT-4 支持 128K，Claude 支持 200K，Gemini 2.5 支持 1M 以上。**SP 不再是"高级特性"，而是长上下文训练的必需品。**

## 🛠 实操指南

### 📋 决策指南：你的场景需要 SP 吗？

```
当前序列长度是多少？
├─ < 16K → 不需要 SP，3D 并行就够
├─ 16K - 64K → 建议 SP=4，Megatron-SP
├─ 64K - 256K → 建议 SP=8，DeepSpeed-Ulysses 或 Megatron-SP
└─ > 256K → Ring Attention + Flash Attention 3
```

**显存快速判断公式**：
```python
# 单层 Attention 的显存占用（激活值）
seq_len = 128000
hidden_dim = 4096
batch_size = 1
precision = 2  # FP16 bytes

attn_mem = batch_size * seq_len * seq_len * hidden_dim * precision
print(f"单层 Attention 激活值: {attn_mem / 1024**3:.1f} GB")
# 128K 序列 × 4096 hidden → 约 2 TB（单层！）
# H100 总显存只有 80 GB → 完全放不下
```

### 🔧 自己动手验：启用 SP 前后的内存对比

```python
# 启用 SP 前的显存需求：
# 单个 Transformer 层
def estimate_layer_mem(seq_len, hidden_dim, batch_size):
    # 参数（W_q, W_k, W_v, W_o, MLP）
    param_mem = 4 * hidden_dim * hidden_dim * 2  # FP16
    # Attention 激活值
    attn_mem = batch_size * seq_len * seq_len * hidden_dim * 2
    # MLP 激活值
    mlp_mem = batch_size * seq_len * hidden_dim * 4 * 2
    return (param_mem + attn_mem + mlp_mem) / 1024**3

# 对比 SP=1 vs SP=8
no_sp = estimate_layer_mem(128000, 4096, 1)
with_sp = estimate_layer_mem(128000 // 8, 4096, 1)  # SP=8 切分序列
print(f"无 SP: {no_sp:.1f} GB/层")
# 无 SP: > 2 TB/层（完全放不下）

print(f"SP=8: {with_sp:.1f} GB/层")
# SP=8: ~32 GB/层（可接受）
```

### ⚠️ 常见误区

- **误区**："SP 和 TP 是一样的，切分方式不同而已"
  - **实际**：TP 切的是 **hidden_dim**（矩阵的列），SP 切的是 **seq_len**（序列的位置）。它们的通信模式也不同：TP 每层都做 All-Reduce，SP 只在 Attention 和 LayerNorm 之间插入通信。**实践中 SP 和 TP 可以共用同一个 All-Reduce 操作**（这也是 Megatron-SP 的设计精妙之处）。

- **误区**："序列越长才需要 SP，4K 序列完全不需要"
  - **实际**：即使序列不长（4K），SP 也可以和其他并行策略结合来**减少激活值显存**，从而允许更大的 batch size 或降低通信。**SP 不是只为了超长序列，它在标准训练中也是一个有用的优化维度。**

- **误区**："SP 是纯显存优化，不影响计算速度"
  - **实际**：SP 减少了每张 GPU 负责的序列长度，Attention 计算量的二次复杂度（O(N²)）变为 O((N/SP)²)，**单卡计算量大幅降低**。但新增了通信开销。在序列长度极大时，这个权衡非常值得。

### 📊 底线数字速查

| 指标 | 优秀 | 及格 | 报警 |
|------|------|------|------|
| 序列长度 | < 16K（不需要 SP） | 16K-128K（需要 SP） | > 128K（必须 SP） |
| SP 显存节省 | > 8× | 4-8× | < 4× |
| SP 通信开销增量 | < 5% | 5-15% | > 15% |
| SP degree vs seq_len 匹配 | seq_len/SP > 1K | seq_len/SP 256-1K | seq_len/SP < 256 |

### 💡 一句话记住

> **"序列并行解决的是 Attention 的'显存二次爆炸'——序列从 4K 到 128K，显存需求从 2GB 涨到 2TB。把序列切到多卡上，每卡只处理一段，让长度扩展从指数变线性。"**

## 对后续的铺垫

SP 解决了长序列训练的显存问题。还有一种并行策略针对的是**模型结构本身**的稀疏性——MoE（混合专家模型）中，每个 token 只激活一部分参数，常规的 TP/DP 无法高效处理这种"不均匀"的计算模式。
