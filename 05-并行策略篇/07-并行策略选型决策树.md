# Q: 这些并行策略哪个最好？— 2026 年选型决策树

## 为什么会有这个问题

现在你已经知道了各种并行策略——DP、TP、PP、SP/CP、EP。每种策略都有各自的最佳场景和约束条件。**没有一种策略是"最好"的，只有"最适合你的模型的"。**

## 解决问题：一个完整的选型框架

### 第一步：确定你的模型状态能不能单卡装下

```
完整训练状态 = 参数量 × 16 B（BF16 权重 + BF16 梯度 + FP32 master + Adam m/v）

模型状态 ÷ 并行度后，单卡能装下吗？
├─ 能（且算力够）→ 只需要 DP（甚至单卡就够）
└─ 不能 →
   ├─ 是单层太大还是层太多？
   │  ├─ 单层参数字节数 > 单卡显存 → 加 TP
   │  └─ 层多、除以 TP 后仍超预算 → 加 PP
   └─ 数据吞吐不够？→ 剩余卡加 DP
```

### 第二步：检查是否需要特殊并行

```
序列是否超长（> 32K tokens）？
├─ 32K-64K → 叠加 Megatron-SP（附着在 TP 组上，不占新卡数）
└─ > 128K → 加 CP（Ring/Ulysses，独立维度，要重新算预算）

模型是否是 MoE 架构？
├─ 是 → 加 EP（从 DP_attn 里切：DP_attn = EP × DP_experts，不是再乘一维）
└─ 否 → 不需要
```

### 第三步：确定具体参数

```
固定约束：
  world = TP × PP × CP × DP_attn
  稠密模型：DP_attn 就是数据并行度，EP=1
  MoE 模型：DP_attn = EP × DP_experts   ← EP 从 DP_attn 池里切，不是额外一维
  SP：附着在 TP 组上，并行度 = TP 度，不占卡数，不进乘法

调整原则：
  1. TP 是通信最频繁的（每层 4 次 All-Reduce）→ 优先满足 NVLink 约束（TP ≤ 8）
  2. 按显存预算定 PP：每卡状态 = 总状态 ÷ (TP×PP×EP) ≤ 每卡预算
     （约 60-65% 显存，留激活余量）；PP 必须整除层数，见 03-PP
  3. 剩余卡全给 DP_attn；MoE 时在 DP_attn 内再按 EP×DP_experts 拆
  4. PP 取 4-8（超大模型 16，需 DualPipe/零气泡配套），并保证 microbatch 数 ≥ 4×P 压气泡

2026 年推荐起始配置：
  < 32 GPU:   TP=8（或 4）, PP=1-4, DP=1-4
  32-256 GPU: TP=8, PP=4-8, DP=4-32
  > 256 GPU:  TP=8, PP=8-16, DP=4-16
```

## 不同模型规模的推荐配置

### 微调场景（已有预训练模型，只做全量微调或 LoRA）

| 模型规模 | GPU 数 | TP | PP | DP | 其他 | 预期 MFU |
|---------|--------|-----|-----|-----|------|---------|
| 7B（LoRA） | 1-8 | 1 | 1 | N | — | 40-50% |
| 7B（全量） | 8 | 1 | 1 | 8 | FSDP2/ZeRO-3（状态 112 GB → 14 GB/卡） | 45-55% |
| 13B（全量） | 8-16 | 1-2 | 1 | 8 | ZeRO-3（状态 208 GB） | 40-50% |
| 34B（全量） | 16-32 | 1-2 | 1-2 | 8-16 | ZeRO-3（状态 544 GB） | 40-50% |

### 预训练场景（从头训练）

| 模型规模 | 最小可用配置（稠密：TP×PP×DP ≤ 卡数） | 推荐配置 | 预期 MFU |
|---------|-------------------------------|---------|---------|
| 7B | 8 卡：TP=8, PP=1, DP=1 | 64 卡：TP=8, PP=1, DP=8 | 50-60% |
| 13B | 8 卡：TP=8, PP=1, DP=1 | 64-128 卡：TP=8, PP=1-2, DP=4-8 | 50-60% |
| 70B | **32 卡：TP=8, PP=4, DP=1**（1.12 TB ÷ 32 = 35 GB/卡）| 128-256 卡：TP=8, PP=4-8, DP=4-8 | 45-55% |
| 405B | **512 卡：TP=8, PP=16, DP=4**（6.48 TB ÷ 128 = 51 GB/卡）| 1024 卡：TP=8, PP=16, DP=8 | 40-50% |
| 1T+ | 1024-2048 卡：TP=8, PP=16-32, DP=4-8 | 2048+ 卡 | 35-45% |

> 参照系：Meta 训练 Llama 3 405B 用的是 TP=8 × PP=16 × DP=128 = **16,384 GPU**。上表的"最小可用"只保证装得下、能跑，吞吐未必划算；PP=16 时务必配足 microbatch（M ≥ 4×P）并考虑 interleaved/ZB 调度压气泡。

### MoE 模型推荐配置（world = TP×PP×EP×DP_experts，EP 从 DP_attn 里切）

每卡训练状态 ≈ `总状态 ÷ (TP×PP×EP)`——专家被 TP、PP、EP 三者共同分片；DP_experts 只复制、不分片。**MoE 的缩放顺序是：先加 EP 到拓扑域上限，再加 DP_experts，TP 保持 1–2。**

| 模型 | 专家数 | 最小可用配置 | 推荐配置 | 每卡状态 | 预期 MFU |
|------|-------|-------------|---------|---------|---------|
| Mixtral 8×7B（47B） | 8 | 32 卡：TP=2, PP=1, EP=8, DP=2 | 64 卡：TP=2, PP=2, EP=8, DP=2 | 24 GB | 40-50% |
| DeepSeek-V2（236B） | 160 | 128 卡：TP=2, PP=4, EP=16, DP=1 | 256 卡：TP=2, PP=4, EP=16, DP=2 | 29.5 GB | 45-55% |
| **DeepSeek-V3（671B）** | **256** | — | **2048 卡：TP=1, PP=16, EP=64, DP=2（公开配置 + DualPipe）** | **10.5 GB** | 35-40% |
| 400B 级 MoE | 128+ | 256 卡：TP=1, PP=4, EP=64, DP=1 | 512-1024 卡：TP=1-2, PP=8, EP=64-128, DP=1-2 | 12-25 GB | 40-50% |

> DeepSeek-V3 是本篇最强的锚点：`2048 = TP1 × PP16 × EP64 × DP_experts2`，`DP_attn = 64×2 = 128`，每卡约 `671B×16B ÷ (1×16×64) = 10.5 GB` 训练状态。**TP=1 不是异常，而是 MoE 的最优解**——省显存交给 EP，省通信靠 DualPipe。

> 表中 Mixtral / DeepSeek-V2 / 400B 级为按本页公式推导的示意配置，非厂商公开值；DeepSeek-V3 为公开配置。

## 2026 年框架的并行能力

| 能力 | FSDP2 + 原生 PyTorch | DeepSpeed | Megatron-Core |
|------|-------------------|-----------|---------------|
| DP | ✅ 原生支持 | ✅ ZeRO-3 | ✅ DP + 数据并行 |
| TP | ⚠️ 需手动配置 | ⚠️ 需结合 Megatron | ✅ **原生支持** |
| PP | ❌ 没有原生 PP | ✅ PipeDream | ✅ 1F1B + Zero Bubble |
| SP/CP | ⚠️ 通过 DCP | ✅ DeepSpeed-Ulysses | ✅ **Megatron-SP + CP** |
| EP | ❌ 不支持 | ✅ DeepSpeed-MoE | ✅ **原生 MoE + EP** |
| 组合 | FSDP2 + TP | ZeRO-3 + Megatron | **TP+PP+DP+CP+EP（5D）** |
| 推荐场景 | **微调/中小模型** | 内存受限/长上下文 | **超大模型预训练** |

## 🛠 实操指南

### 📋 决策指南：一句话总结，你的模型怎么配

```python
def recommend(model_size_B, num_gpus, num_layers=80, seq_len=4096,
              is_moe=False, num_experts=0, experts_per_gpu=4,
              vram_gb=80, nvlink_domain=8):
    """预训练选型：算显存账 → 定 TP → 定 PP（整除层数）→ 定 EP（MoE）→ DP。
    world = TP×PP×CP×DP_attn；MoE 时 DP_attn = EP×DP_experts。
    只覆盖 TP/PP/EP 的切分；微调/LoRA 请用 FSDP2/ZeRO-3（见 08 篇）。"""
    budget = vram_gb * 0.65                  # 留 ~35% 给激活、NCCL buffer 等
    state = model_size_B * 16                # 16 B/参数：权重+梯度+FP32 master+Adam

    # 1) TP：稠密模型才上 8；MoE 保持 1–2（省显存交给 EP）
    if is_moe:
        tp = 1 if num_experts >= 64 else min(2, nvlink_domain)
    else:
        tp = min(nvlink_domain, 8) if (model_size_B > 13 and num_gpus >= 8) else 1

    # 2) PP + EP：从小到大试 PP，直到每卡状态进预算
    pp, ep = 1, 1
    while pp <= num_layers:
        dp_attn = max(1, num_gpus // (tp * pp))
        if is_moe and num_experts:
            ep = max(1, min(num_experts // experts_per_gpu, dp_attn * tp))
            while dp_attn % ep and ep > 1:    # EP 必须整除 DP_attn
                ep -= 1
        if state / (tp * pp * ep) <= budget:
            break
        pp *= 2

    dp_attn = max(1, num_gpus // (tp * pp))
    dp_experts = max(1, dp_attn // ep)
    total = tp * pp * ep * dp_experts
    per_card = state / (tp * pp * ep)

    print(f"{model_size_B}B / {num_gpus} GPU → TP={tp}, PP={pp}, EP={ep}, "
          f"DP_experts={dp_experts}{'（建议 +SP）' if seq_len > 32768 else ''}")
    print(f"  world = TP×PP×EP×DP_experts = {total} "
          f"({'✅ ≤ 可用卡数' if total <= num_gpus else '❌ 超出，需加 PP'}）")
    print(f"  每卡训练状态 ≈ {per_card:.0f} GB（预算 {budget:.0f} GB）")
    if per_card > budget:
        print("  ❌ 即使加到该 PP 仍超预算：考虑 ZeRO-3/Offload、更大显存卡，或拆成更小的模型")
    if num_layers % pp:
        print(f"  ⚠️ {num_layers} 层不能被 PP={pp} 整除：需不均匀切分，"
              f"或把 embedding/head 计入（如 126+2=128），或改用因子 PP")
    if pp >= 8:
        print(f"  ⚠️ PP={pp}：microbatch 数需 ≥ {4 * pp}，并考虑 interleaved/Zero Bubble")
    if is_moe:
        print("  ⚠️ EP 的 All-to-All 域尽量限制在单机/单机架内")
    return tp, pp, ep, dp_experts

# 示例
recommend(70, 256)                                   # 70B 稠密
# → TP=8, PP=4, EP=1, DP=8；world=256；每卡 35 GB
recommend(405, 1024, num_layers=126)                 # 405B 稠密
# → TP=8, PP=16, EP=1, DP=8；world=1024；每卡 ~51 GB（126 层需不均匀切分）
recommend(671, 2048, num_layers=61, is_moe=True, num_experts=256)
# → TP=1, PP=4, EP=64, DP_experts=8；world=2048；每卡 ~42 GB
#   DeepSeek-V3 公开配置为 PP=16/DP=2，属同等显存下的调度取舍（DualPipe 压气泡）
```

### ⚠️ 常见误区

- **误区**："总 GPU 数 = TP×PP×DP×SP×EP，五个数相乘"
  - **实际**：SP 附着在 TP 组上、不占卡数（并行度 = TP 度）；EP 也不是额外的第六维，而是从 DP_attn 池里切出来的。正确写法是 `world = TP×PP×CP×DP_attn`，其中 MoE 时 `DP_attn = EP×DP_experts`。把 SP 乘进去会算出不存在的集群规模；把 EP 和 DP_attn 同时乘又会重复计算。

- **误区**："并行策略越复杂越好，5D 并行肯定比 3D 强"
  - **实际**：每增加一个并行维度，就增加一层通信开销和调度复杂度。**如果 3D 并行（TP+PP+DP）已经能让 MFU 达到 50%+，加 CP/EP 可能反而因为通信开销降低整体效率。** 只在有明确需求（超长序列 / MoE）时增加维度。

- **误区**："只要 GPU 够多，什么模型都能训练"
  - **实际**：Amdahl 定律——串行部分（通信、同步）不随 GPU 数增加而减少。当 DP degree 很大时，跨机梯度 All-Reduce 的通信时间占比会上升。**GPU 翻倍，速度可能只提升 60-80%**（取决于通信占比，需按你的配置实测）。

- **误区**："MFU 是衡量并行策略好坏的唯一标准"
  - **实际**：MFU 只衡量**算力利用率**，不衡量显存效率、通信延迟、可维护性。有时候选择 MFU 稍低但实现更简单的方案（如 FSDP2 而非 Megatron），长期维护成本更低。

### 📊 底线数字速查

| 场景 | 推荐并行方案 | 典型 GPU 数 | 预期 MFU | 实现复杂度 |
|------|------------|-----------|---------|-----------|
| 单卡微调 | 无 | 1 | 30-40% | 极低 |
| 小规模训练（< 7B） | DP（FSDP2/ZeRO-3） | 8-32 | 50-60% | 低 |
| 中等训练（7B-34B） | TP+DP | 32-128 | 45-55% | 中 |
| 大规模训练（70B-405B） | TP+PP+DP（3D） | 128-1024 | 40-55% | 高 |
| 超长上下文（> 128K） | 3D + CP（SP 附着 TP） | 256-1024 | 35-50% | 高 |
| MoE 大模型 | 3D + EP（5D） | 512-2048 | 40-50% | 极高 |

### 💡 一句话记住

> **"选型顺序比选型结果重要：先用 16 B/参数账本算每卡预算 → 定 TP（≤ 8，NVLink 域内；MoE 取 1–2）→ 定 PP（必须整除层数，把状态压进预算）→ 剩余卡给 DP_attn；MoE 时把 DP_attn 拆成 EP × DP_experts。world = TP×PP×CP×DP_attn——SP 不占卡数，EP 是 DP_attn 内部的一维。"**

## 对后续的铺垫

你知道了选择哪种并行策略，但怎么在实际中落地？不同的训练框架对并行策略的支持深度不同：
- **FSDP2**：PyTorch 原生，支持 DP + TP，推荐中小模型
- **DeepSpeed**：支持 ZeRO-3 + MoE + Ulysses，内存受限场景首选
- **Megatron-Core**：支持 5D 并行，超大模型预训练的工业标准
