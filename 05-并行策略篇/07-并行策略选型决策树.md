# Q: 这些并行策略哪个最好？— 2026 年选型决策树

## 为什么会有这个问题

现在你已经知道了各种并行策略——DP、TP、PP、SP/CP、EP。每种策略都有各自的最佳场景和约束条件。**没有一种策略是"最好"的，只有"最适合你的模型的"。**

## 解决问题：一个完整的选型框架

### 第一步：确定你的模型状态能不能单卡装下

```
完整训练状态 = 参数量 × 16 B（BF16 权重 + BF16 梯度 + FP32 master + Adam m/v）

模型状态 ÷ 并行度后，单卡能装下吗？
├─ 能（且算力够）→ 只需要 DP（甚至单卡就够）
└─ 不能 →
   ├─ 是单层太大还是层太多？
   │  ├─ 单层参数字节数 > 单卡显存 → 加 TP
   │  └─ 层多、除以 TP 后仍超预算 → 加 PP
   └─ 数据吞吐不够？→ 剩余卡加 DP
```

### 第二步：检查是否需要特殊并行

```
序列是否超长（> 32K tokens）？
├─ 32K-64K → 叠加 Megatron-SP（附着在 TP 组上，不占新卡数）
└─ > 128K → 加 CP（Ring/Ulysses，独立维度，要重新算预算）

模型是否是 MoE 架构？
├─ 是 → 加 EP（从 DP 组内组织，EP ≤ DP×TP；不是再乘一维）
└─ 否 → 不需要
```

### 第三步：确定具体参数

```
固定约束：
  总 GPU 数 = TP × PP × DP          ← 就是这三个数相乘
  SP：附着在 TP 组上，不占卡数，不进乘法
  EP：MoE 时占用 DP 组内的卡（EP ≤ DP×TP 视实现），不进乘法

调整原则：
  1. TP 是通信最频繁的（每层 4 次 All-Reduce）→ 优先满足 NVLink 约束（TP ≤ 8）
  2. 按显存预算定 PP：训练状态 ÷ (TP×PP) ≤ 每卡预算（约 60-65% 显存，留激活余量）
  3. 剩余卡全给 DP；MoE 时在 DP 组内再分 EP
  4. PP 取 4-8（超大模型 16），并保证 microbatch 数 ≥ 4×P 压气泡

2026 年推荐起始配置：
  < 32 GPU:   TP=8（或 4）, PP=1-4, DP=1-4
  32-256 GPU: TP=8, PP=4-8, DP=4-32
  > 256 GPU:  TP=8, PP=8-16, DP=4-16
```

## 2026 年框架的并行能力

| 能力 | FSDP2 + 原生 PyTorch | DeepSpeed | Megatron-Core |
|------|-------------------|-----------|---------------|
| DP | ✅ 原生支持 | ✅ ZeRO-3 | ✅ DP + 数据并行 |
| TP | ⚠️ 需手动配置 | ⚠️ 需结合 Megatron | ✅ **原生支持** |
| PP | ❌ 没有原生 PP | ✅ PipeDream | ✅ 1F1B + Zero Bubble |
| SP/CP | ⚠️ 通过 DCP | ✅ DeepSpeed-Ulysses | ✅ **Megatron-SP + CP** |
| EP | ❌ 不支持 | ✅ DeepSpeed-MoE | ✅ **原生 MoE + EP** |
| 组合 | FSDP2 + TP | ZeRO-3 + Megatron | **TP+PP+DP+CP+EP（5D）** |
| 推荐场景 | **微调/中小模型** | 内存受限/长上下文 | **超大模型预训练** |

## 🛠 实操指南

### 📋 决策指南：一句话总结，你的模型怎么配

```python
def recommend(model_size_B, num_gpus, seq_len=4096, is_moe=False, num_experts=0, vram_gb=80):
    """选型顺序：每卡模型状态预算 → 选 TP/PP → 剩余卡做 DP → MoE 再分 EP。
    总卡数 = TP×PP×DP；SP 不占卡数；EP 从 DP 组内组织。"""
    budget = vram_gb * 0.65          # 留 ~35% 给激活、NCCL buffer 等
    state = model_size_B * 16        # 16 B/参数：权重+梯度+FP32 master+Adam

    # 1) TP：NVLink 域内（≤ 8）
    tp = 8 if num_gpus >= 8 else max(1, num_gpus)

    # 2) PP：把训练状态压进每卡预算
    pp = 1
    while state / (tp * pp) > budget and pp < 64:
        pp *= 2                      # 1→2→4→8→16→32

    # 3) DP：剩余卡全部给数据并行
    dp = max(1, num_gpus // (tp * pp))

    # 4) MoE：EP ≤ DP（从 DP 组内组织），不是再乘一维
    ep = min(num_experts, dp) if (is_moe and num_experts) else 1

    # 5) 长序列：seq > 32K 时建议叠加 Megatron-SP（不改变总卡数）；>128K 考虑 CP
    need_sp = seq_len > 32768

    total = tp * pp * dp
    print(f"{model_size_B}B / {num_gpus} GPU → TP={tp}, PP={pp}, DP={dp}, EP={ep}"
          f"{'（建议 +SP）' if need_sp else ''}")
    print(f"  总卡数 = TP×PP×DP = {total}（{'✅ ≤ 可用卡数' if total <= num_gpus else '❌ 超出，加 PP'}）")
    print(f"  每卡训练状态 ≈ {state/(tp*pp):.0f} GB（预算 {budget:.0f} GB）")
    if pp >= 8:
        print("  ⚠️ PP 较大：microbatch 数 ≥ 4×PP，并考虑 interleaved/ZB 调度压气泡")
    return tp, pp, dp, ep

# 示例
recommend(70, 256)                                  # 70B, 256 GPU
# → TP=8, PP=4, DP=8；总 256 ✅；每卡 35 GB
recommend(405, 1024)                                # 405B, 1024 GPU
# → TP=8, PP=16, DP=8；总 1024 ✅；每卡 ~51 GB
recommend(236, 512, is_moe=True, num_experts=160)   # DeepSeek-V2, 512 GPU
# → TP=8, PP=16, DP=4, EP=4；总 512 ✅；每卡 ~30 GB
```

### ⚠️ 常见误区

- **误区**："总 GPU 数 = TP×PP×DP×SP×EP，五个数相乘"
  - **实际**：SP 附着在 TP 组上、不占卡数；EP 从 DP 组内组织、不简单相乘。**总卡数 = TP×PP×DP**。把 SP=4、EP=16 也乘进去，会算出一个不存在的集群规模（比如 405B "8×8×16×4 = 4096 卡"，而场景只有 512-1024 卡）。

- **误区**："并行策略越复杂越好，5D 并行肯定比 3D 强"
  - **实际**：每增加一个并行维度，就增加一层通信开销和调度复杂度。**如果 3D 并行（TP+PP+DP）已经能让 MFU 达到 50%+，加 CP/EP 可能反而因为通信开销降低整体效率。** 只在有明确需求（超长序列 / MoE）时增加维度。

- **误区**："只要 GPU 够多，什么模型都能训练"
  - **实际**：Amdahl 定律——串行部分（通信、同步）不随 GPU 数增加而减少。当 DP degree 很大时，跨机梯度 All-Reduce 的通信时间占比会上升。**GPU 翻倍，速度可能只提升 60-80%**（256→512 卡时）。

- **误区**："MFU 是衡量并行策略好坏的唯一标准"
  - **实际**：MFU 只衡量**算力利用率**，不衡量显存效率、通信延迟、可维护性。有时候选择 MFU 稍低但实现更简单的方案（如 FSDP2 而非 Megatron），长期维护成本更低。

### 📊 底线数字速查

| 场景 | 推荐并行方案 | 典型 GPU 数 | 预期 MFU | 实现复杂度 |
|------|------------|-----------|---------|-----------|
| 单卡微调 | 无 | 1 | 30-40% | 极低 |
| 小规模训练（< 7B） | DP（FSDP2/ZeRO-3） | 8-32 | 50-60% | 低 |
| 中等训练（7B-34B） | TP+DP | 32-128 | 45-55% | 中 |
| 大规模训练（70B-405B） | TP+PP+DP（3D） | 128-1024 | 40-55% | 高 |
| 超长上下文（> 128K） | 3D + CP（SP 附着 TP） | 256-1024 | 35-50% | 高 |
| MoE 大模型 | 3D + EP（5D） | 512-2048 | 40-50% | 极高 |

### 💡 一句话记住

> **"选型顺序比选型结果重要：先用 16 B/参数账本算每卡预算 → 定 TP（≤ 8，NVLink 域内）→ 定 PP（把训练状态压进预算）→ 剩余卡给 DP，MoE 时在 DP 组内分 EP。总卡数就是 TP×PP×DP——SP 不占卡数，EP 不进乘法。"**

## 对后续的铺垫

你知道了选择哪种并行策略，但怎么在实际中落地？不同的训练框架对并行策略的支持深度不同：
- **FSDP2**：PyTorch 原生，支持 DP + TP，推荐中小模型
- **DeepSpeed**：支持 ZeRO-3 + MoE + Ulysses，内存受限场景首选
- **Megatron-Core**：支持 5D 并行，超大模型预训练的工业标准
