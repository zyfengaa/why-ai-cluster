# Q: 这些并行策略哪个最好？— 2026 年选型决策树

## 为什么诞生这个问题？

现在你已经知道了五种并行策略——DP、TP、PP、SP、EP。每种策略都有各自的最佳场景和约束条件。**没有一种策略是"最好"的，只有"最适合你的模型的"。**

## 解决问题：一个完整的选型框架

### 第一步：确定你的模型能不能单卡装下

```
模型能不能单卡装下？
├─ 能（< 7B）→ 只需要 DP（甚至单卡就够）
└─ 不能 / 训练太慢 →
   ├─ 是单层太大还是层太多？
   │  ├─ 单层大（hidden_dim 超显存）→ 加 TP
   │  └─ 层太多 → 加 PP
   └─ 数据吞吐不够？→ 加 DP
```

### 第二步：检查是否需要特殊并行

```
序列是否超长（> 16K tokens）？
├─ 是 → 加 CP（Context Parallel）
│      （Ulysses 是具体实现之一；硬约束：head 数需被 CP 度整除）
└─ 否 → 不需要

模型是否是 MoE 架构？
├─ 是 → 加 EP（复用 DP×CP 的 rank，不额外占卡）
└─ 否 → 不需要
```

### 第三步：确定具体参数

```
固定约束：
  TP degree = NVLink 域内 GPU 数（通常 8）
  总 GPU 数 = TP × PP × CP × DP
    （SP 与 TP 同开、共用同一进程组，不是独立相乘维；
      EP 复用 DP×CP 的 rank，也不额外乘卡数）

调整原则（按通信量排序）：TP > EP > PP > DP
  1. TP 最重（每层都要 All-Reduce）→ 优先满足 TP 的 NVLink 约束
  2. EP 次重（每层 2 次 All-to-All）→ 也尽量放高速域内
  3. PP（P2P）与 DP（每步一次梯度 All-Reduce，可与 backward 重叠）最轻
     → 可跨节点的是 PP 与 DP
  4. CP 只在长序列时才需要 → 不是必须的
    
2026 年推荐起始配置：
  < 32 GPU:   TP=8（或 4）, PP=1-2, CP=1, DP=1-2
  32-256 GPU: TP=8, PP=2-4, CP=1-2, DP=2-8
  > 256 GPU:  TP=8, PP=8, CP=2-4, DP=4-32
```

## 不同模型规模的推荐配置

### 微调场景（已有预训练模型，只做全量微调或 LoRA）

| 模型规模 | GPU 数 | TP | PP | DP | 其他 | 预期 MFU |
|---------|--------|-----|-----|-----|------|---------|
| 7B（LoRA） | 1-8 | 1 | 1 | 1-8 | — | 40-50% |
| 7B（全量） | 8 | 2 | 1 | 4 | ZeRO/FSDP 省优化器状态 | 45-55% |
| 13B（全量） | 8-16 | 8 | 1 | 1-2 | — | 40-50% |
| 34B（全量） | 16-32 | 8 | 2 | 1-2 | — | 40-50% |

**注**：7B 全量微调放不下单卡的原因是**优化器状态**（16 bytes/param × 7e9 ≈ 112 GB），解法是 **ZeRO/FSDP 或 TP=2**。用 TP=8 只为省 1/8 权重，却引入每层 4 次 AllReduce，通信开销远超收益，故不推荐。

### 预训练场景（从头训练）

| 模型规模 | GPU 数 | TP | PP | CP | DP | 预期 MFU |
|---------|--------|-----|-----|-----|-----|---------|
| 7B | 32-64 | 8 | 1 | 1 | 4-8 | 50-60% |
| 13B | 64-128 | 8 | 2 | 1 | 4-8 | 50-60% |
| 70B | 128-256 | 8 | 4 | 1 | 4-8 | 45-55% |
| 130B | 256-512 | 8 | 8 | 1 | 4-8 | 45-55% |
| 405B | 512-1024 | 8 | 16 | 2 | 2-4 | 40-50% |
| 1T+ | 1024-2048 | 8 | 16 | 4 | 2-4 | 35-45% |

**约束**：`TP × PP × CP × DP = GPU 数`（EP 复用 DP×CP 的 rank，不额外乘卡数）。超大模型（≥ 405B）单靠这四维仍装不下按 16 bytes/参数计的优化器状态，需叠加 ZeRO/FSDP 或 CPU Offload。

### MoE 模型推荐配置

| 模型 | 专家数 | GPU 数 | TP | EP | PP | DP | 预期 MFU |
|------|-------|--------|-----|-----|-----|-----|---------|
| Mixtral 8×7B | 8 | 32-64 | 8 | 4-8 | 1 | 4-8 | 40-50% |
| DeepSeek-V2 (236B) | 162 | 128-256 | 8 | 4-8 | 4 | 4-8 | 45-55% |
| 400B MoE | 128 | 512-1024 | 8 | 8-16 | 8 | 8-16 | 40-50% |

**约束**：`TP × PP × DP = GPU 数`（EP ≤ DP，复用 DP×CP 的 rank，不额外乘卡数）。

## 2026 年框架的并行能力

| 能力 | FSDP2 + 原生 PyTorch | DeepSpeed | Megatron-Core |
|------|-------------------|-----------|---------------|
| DP | ✅ 原生支持 | ✅ ZeRO-3 | ✅ DP + 数据并行 |
| TP | ⚠️ 需手动配置 | ⚠️ 需结合 Megatron | ✅ **原生支持** |
| PP | ❌ 没有原生 PP | ✅ PipeDream | ✅ 1F1B + Zero Bubble |
| SP / CP | ⚠️ DTensor `Shard(1)` 布局 + `parallelize_module` | ✅ DeepSpeed-Ulysses | ✅ **Megatron-SP + CP** |
| EP | ⚠️ TorchTitan 已支持 MoE/EP（较新版本）| ✅ DeepSpeed-MoE | ✅ **原生 MoE + EP** |
| 组合 | FSDP2 + TP4 | ZeRO-3 + Megatron | **TP+PP+DP+CP+EP 5D** |
| 推荐场景 | **微调/中小模型** | 内存受限/长上下文 | **超大模型预训练** |

## 🛠 实操指南

### 📋 决策指南：一句话总结，你的模型怎么配

```python
def recommend_parallelism(model_size_B, num_gpus, seq_len, is_moe=False):
    """根据模型和硬件推荐并行配置。
    保证 tp × pp × cp × dp == num_gpus（cp=1 时即 tp × pp × dp == num_gpus）；
    EP 复用 DP 所在的 rank 空间，不额外占卡数。
    """
    if num_gpus < 1:
        raise ValueError("num_gpus 必须 ≥ 1")

    # 1) TP：优先 NVLink 域，最多 8，且必须整除总卡数
    tp = min(8, num_gpus)
    while tp > 1 and num_gpus % tp != 0:
        tp //= 2
    remaining = num_gpus // tp

    # 2) CP：只有长序列才开，取 2 的幂且能整除剩余组数
    cp = 1
    if seq_len > 32768:
        want = min(remaining, seq_len // 32768)
        while want > 1 and (remaining % want != 0 or want > 16):
            want //= 2
        cp = max(1, want)
    remaining //= cp

    def per_card_gb(pp_):
        # 16 bytes/参数（fp16 权重 2 + fp16 梯度 2 + fp32 master 4 + Adam m 4 + v 4）
        return model_size_B * 1e9 * 16 / (tp * pp_) / 1024**3

    # 3) PP：先按 4-8 取能整除剩余组数的值
    pp = 1
    for cand in (8, 4, 2, 1):
        if remaining % cand == 0:
            pp = cand
            break

    # 显存兜底：每卡装不下时把 PP 加到 16（仍须整除 remaining，且不超过文件给定的 PP 上限）
    if per_card_gb(pp) > 80:
        for cand in (16,):
            if remaining % cand == 0 and per_card_gb(cand) <= 80:
                pp = cand
                break

    # 4) DP 吃掉剩下的卡数
    dp = remaining // pp

    # 5) EP：MoE 时复用 DP 所在的 rank 空间（EP ≤ DP），不额外乘卡数
    ep = min(dp, 16) if is_moe else 1

    total = tp * pp * cp * dp
    print(f"推荐配置（{model_size_B}B, {num_gpus} GPU, seq={seq_len}）:")
    print(f"  TP={tp}, PP={pp}, CP={cp}, DP={dp}, EP={ep}")
    print(f"  总 GPU: {total}（= TP×PP×CP×DP）")
    print(f"  每卡权重: {model_size_B * 1e9 * 2 / (tp * pp) / 1024**3:.0f} GB")
    print(f"  每卡总显存需求（16 B/参数）: {per_card_gb(pp):.0f} GB")

    if total != num_gpus:
        print("⚠️ 配置未能用满全部卡数，请检查约束")
    if per_card_gb(pp) > 80:
        print("⚠️ 每卡参数+优化器状态超过 80 GB 单卡上限，需叠加 ZeRO/CPU Offload")

    return tp, pp, cp, dp, ep

# 示例调用
recommend_parallelism(70, 256, 4096)          # 70B, 256 GPU, 4K 序列
print("---")
recommend_parallelism(405, 1024, 128*1024)    # 405B, 1024 GPU, 128K 序列
print("---")
recommend_parallelism(236, 512, 8192, True)   # DeepSeek-V2, 512 GPU
```

### ⚠️ 常见误区

- **误区**："并行策略越复杂越好，5D 并行肯定比 3D 强"
  - **实际**：每增加一个并行维度，就增加一层通信开销和调度复杂度。**如果 3D 并行（TP+PP+DP）已经能让 MFU 达到 50%+，加 SP/EP 可能反而因为通信开销降低整体效率。** 只在有明确需求时增加并行维度。

- **误区**："只要 GPU 够多，什么模型都能训练"
  - **实际**：Amdahl 定律——串行部分（通信、同步）不随 GPU 数增加而减少。当每步梯度 All-Reduce 的时间接近计算时间时（经验上 DP degree > 64，具体阈值取决于梯度大小与跨机带宽），扩展收益基本消失。**GPU 翻倍，速度可能只提升 60-80%**（256→512 卡时）。

- **误区**："MFU 是衡量并行策略好坏的唯一标准"
  - **实际**：MFU 只衡量**算力利用率**，不衡量显存效率、通信延迟、可维护性。有时候选择 MFU 稍低但实现更简单的方案（如 FSDP2 而非 Megatron），长期维护成本更低。

### 📊 底线数字速查

| 场景 | 推荐并行方案 | 典型 GPU 数 | 预期 MFU | 实现复杂度 |
|------|------------|-----------|---------|-----------|
| 单卡微调 | 无 | 1 | 30-40% | 极低 |
| 小规模训练（< 7B） | DP（FSDP2） | 8-32 | 50-60% | 低 |
| 中等训练（7B-34B） | TP+DP | 32-128 | 45-55% | 中 |
| 大规模训练（70B-405B） | TP+PP+DP（3D） | 128-1024 | 40-55% | 高 |
| 长上下文（> 32K） | 3D + SP（4D） | 256-1024 | 35-50% | 高 |
| MoE 大模型 | 3D + SP + EP（5D） | 512-2048 | 40-50% | 极高 |

### 💡 一句话记住

> **"没有最好的并行策略，只有最适合你模型的——TP 固定 8（NVLink 域内），PP 放 4-8（跨节点最友好），DP 撑满剩下的。只有当序列超长或模型是 MoE 时，才加 SP 和 EP。复杂度本身也是成本。"**

## 对后续的铺垫

你知道了选择哪种并行策略，但怎么在实际中落地？不同的训练框架对并行策略的支持深度不同：
- **FSDP2**：PyTorch 原生，支持 DP + TP，推荐中小模型
- **DeepSpeed**：支持 ZeRO + MoE + Ulysses（长上下文的实现之一），内存受限场景首选
- **Megatron-Core**：支持 5D 并行，超大模型预训练的工业标准
