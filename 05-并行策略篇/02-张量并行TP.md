# Q: 显存放不下整个模型怎么办？— 张量并行（TP）

## 为什么诞生这个问题？

数据并行要求每张 GPU 都有完整的模型副本。但当模型大到 **单张 GPU 连一层都放不下** 时（比如 Llama 405B 的注意力层参数超过 80 GB），DP 即使配上 ZeRO-3 也无能为力——因为 ZeRO-3 分片的是**跨层的参数**，不是**层内的参数**。

**核心矛盾**：一层就是一个巨大的矩阵（如 [hidden_dim × hidden_dim]），单个 GPU 连这个矩阵都装不下。

## 解决什么问题：张量并行（Tensor Parallelism，TP）

TP 的核心思想：**把一层内的矩阵切成多份，每张 GPU 算一份，然后合并结果。**

### Megatron-LM 的 TP 方案（最广泛使用的实现）

以 Transformer 的 MLP 层为例（hidden_dim = 4096）：

```
原始计算：Y = GeLU(X × W)

TP 列切分：
W = [W1 | W2]  （把 4096×4096 的矩阵从中间切成两半）
GPU 0: Z0 = X × W1  → 算左半部分
GPU 1: Z1 = X × W2  → 算右半部分
（不做 All-Gather：Z 保持切分状态 [Z0 | Z1]，直接喂给下面的行切分层）

TP 行切分：
W = [W_up; W_down]  （上下切）
GPU 0: Y0 = Z0 × W_up
GPU 1: Y1 = Z1 × W_down
然后 All-Reduce 求和 → Y = Y0 + Y1
```

**关键设计**：列切分后接行切分，只需要**一次 All-Reduce** 而不是两次，大幅减少通信开销。

### 为什么 TP 对通信要求极高

每一个 Transformer 层有 **2 个 TP 块**（Attention 输出投影 + MLP 下投影），每个块前向 1 次 All-Reduce、反向 1 次。以 70B 模型为例：
- Transformer 层数：80 层
- 每层 TP 通信：4 次 All-Reduce（前向 2 + 反向 2）
- 通信总量：80 × 4 × hidden_dim = 非常巨大的同步量

**这就是为什么 TP 必须限制在 NVLink 域内**（TP ≤ 8，对应一个 DGX 机箱）。一旦跨机，带宽从 900 GB/s（NVLink 4）掉到 100 GB/s（IB），性能直接腰斩。

## 优缺点

| 优点 | 缺点 |
|------|------|
| ✅ **打破单卡内存限制**：单层再大也能切 | ❌ **通信极其频繁**：每层都要同步 |
| ✅ **数学等价**：没有近似误差 | ❌ **必须限制在 NVLink 域内**：跨机 TP 性能灾难 |
| ✅ **不需要修改优化器** | ❌ **TP degree 受显卡数限制**：TP=8 需要至少 8 卡 |
| ✅ **和 DP/PP 正交组合** | ❌ **实现复杂**：需要框架级支持（Megatron-Core） |

## 实际经验

### TP degree 怎么选？

| TP degree | 适用场景 | 瓶颈 |
|----------|---------|------|
| TP=1（不切） | 小模型或推理 | 不需要 |
| TP=2 | 中等模型（7B-13B），4 卡节点 | 通信适中 |
| TP=4 | 13B-34B 模型 | 通信较多，适合 NVLink |
| **TP=8** | **70B+ 模型，8 卡 DGX** | **最常用配置** |
| TP > 8 | 极少使用 | 跨机通信太慢，得不偿失 |

**一条经验**：TP degree 总是设为 1、2、4 或 8 —— 对应单节点内的 GPU 数。让 TP 跨节点几乎总是错误的。

### TP 的显存账本（16 bytes/参数）

TP=8 时每张 GPU 只存 1/8 的**权重**——但显存账本是 **16 bytes/参数**（fp16 权重 2 + fp16 梯度 2 + fp32 master 权重 4 + Adam 动量 4 + 方差 4），TP 会把这些一并按参数切分，**每张卡仍按自己那份参数承担完整的 16 bytes/param**：

- 70B 模型：70e9 × 16 B = 1120 GB（全量）
- TP=8 后每卡：70e9 / 8 × 16 B = **140 GB/卡**（远超 H100 的 80 GB）
- 再加激活值，单靠 TP=8 一张 H100 装不下
- 要放下必须叠加 PP ≥ 2 或 ZeRO

## 🛠 实操指南

### 📋 决策指南：什么时候需要 TP？

```
能单卡装下模型？（参数 + 梯度 + 优化器状态 + 激活值）
├─ 能 → 只用 DP/ZeRO 就够了
└─ 不能 →
   └─ 是单层太大还是层太多？
      ├─ 单层太大（hidden_dim > 单卡显存）→ TP 必须
      └─ 层太多但单层不大 → 用 PP（下一篇）就够了
```

**2026 年典型判断**：

| 模型 | 参数显存 | 单层大小（仅 attention 权重）| 需要 TP？ | 推荐 TP degree |
|------|---------|---------------------------|----------|---------------|
| Llama 3 8B | ~16 GB | ~128 MB | ❌ 不需要 | TP=1 |
| Llama 3 70B | ~140 GB | ~512 MB | ✅ 建议 | TP=8 |
| Llama 3 405B | ~810 GB | ~2 GB | ✅ 必须 | TP=8 |
| GPT-4 (1.8T) | ~3.6 TB | ~8 GB | ✅ 必须 | TP=8 |

**注**：「单层大小」只计 Attention 权重（W_q / W_k / W_v / W_o ≈ 4 × hidden_dim² × 2 bytes，忽略 GQA 的 KV 压缩），不含 MLP 与激活值。

### 🔧 自己动手验：理解 TP 的通信量

```python
# 计算 TP 每步的通信量
hidden_dim = 8192  # Llama 3 70B 的 hidden dim
tp_degree = 8

# 每层每步通信量 ≈ 8·b·s·h·bytes
#   = 4 次 AllReduce（前向 2 + 反向 2）× 每次 b·s·h·bytes × 环状系数 2(N-1)/N ≈ 2
batch_size = 4
seq_len = 4096
precision_bytes = 2  # bf16

per_layer_comm = 8 * hidden_dim * batch_size * seq_len * precision_bytes  # ≈ 2 GB/层
total_layers = 80

total_comm = per_layer_comm * total_layers
print(f"TP 每步通信量: {total_comm / 1024**3:.1f} GB")
# 70B 模型 TP=8：每步约 160 GB

# 如果 TP 跨节点（IB 100 GB/s）：通信时间 ≈ 1.6 s
# 如果 TP 在节点内（NVLink 900 GB/s）：通信时间 ≈ 180 ms
```

### ⚠️ 常见误区

- **误区**："TP 就是数据并行的变种，实现起来差不多"
  - **实际**：TP 和数据并行完全不同。数据并行通信**每次迭代一次**（All-Reduce 梯度），TP 通信**每个 Transformer 层四次**（前向 2 次 + 反向 2 次 All-Reduce）。**TP 的通信频率是 DP 的 320 倍（70B 模型 80 层 × 每层 4 次 = 320 次；DP 每步仅 1 次梯度 AllReduce）。** 这就是为什么 TP 对通信要求极其苛刻。

- **误区**："TP 的 degree 可以任意大，越大显存越省"
  - **实际**：TP degree 受限于**NVLink 域内的 GPU 数**——典型值是 8（一个 DGX 机箱）。TP=16 意味着跨两个机箱，通信只能走 InfiniBand，**TP 带来的好处可能被通信开销完全抵消**。Megatron-Core 团队建议 TP 永远不要跨节点。

- **误区**："TP 不改变计算结果，所以没有精度问题"
  - **实际**：理论上 TP 是数学等价的，但实际中矩阵切分后的 GEMM 计算顺序不同可能导致**浮点舍入误差的微小差异**。虽然这些差异通常不影响收敛（在统计噪声范围内），但在某些数值敏感的场景（如强化学习训练）中可能导致不一致。

### 📊 底线数字速查

| 指标 | 优秀 | 及格 | 报警 |
|------|------|------|------|
| TP degree | ≤ 8（NVLink 域内） | ≤ 4 | > 8（跨节点） |
| TP 通信占比 | < 10% | 10-30% | > 30% |
| All-Reduce 有效带宽 busbw（NVLink 4，8 卡，消息 ≥ 1 GB） | > 300 GB/s | 200-300 GB/s | < 200 GB/s |
| 模型层大小 vs 单卡显存 | < 30% | 30-70% | > 70% |
| TP=8 时 70B 每步通信量 | < 100 GB | 100-200 GB | > 200 GB |

### 💡 一句话记住

> **"张量并行把一层大矩阵切成多份——每张 GPU 只算一层的一个切片，然后合并。但它有个死穴：通信太频繁，绝对不能跨节点。记住：TP 绑死 NVLink，TP degree 永远等于机箱内的 GPU 数。"**

## 对后续的铺垫

TP 解决了"单层太大"的问题。但如果模型**层数太多**（比如 80 层甚至 120 层）呢？

TP 把每一层的计算拆分到了多个 GPU，但**所有层还是依次计算的**——GPU 0 算完第 1 层才能算第 2 层，中间的空闲时间被浪费了。

解决这个问题的思路是：**把不同层放到不同的 GPU 上，像流水线一样同时计算。**
