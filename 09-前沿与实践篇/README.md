# 第九篇：前沿与实践篇 — 看完大集群，然后动手

## 本篇导读

前面八章讲的原理，最终都指向两个问题：**最大的集群是怎么设计的？你自己能不能搭一个？**

本篇先用真实的超大集群（Meta、xAI、Google、Stargate）做对照，把"规模放大后哪些问题变了"讲清楚——供电、液冷、网络拓扑、故障率；再用一篇文章带你从 2 台机器搭起自己的学习集群，最后给出完整的学习路径。

**因果链**：集群规模膨胀 → 供电/散热成为第一约束 → 液冷从可选项变成分场景必选 → 内存墙催生 CXL/光互联等新互联 → 但入门不需要 10 GW——2 台机器就能验证全部原理 → 学完之后的路径是推理集群、TCO 与故障定位

## 阅读建议

- **只想看结论**：读每篇的"一句话记住"和"底线数字速查"。
- **打算动手**：直接跳到 04 篇，按"开机后必做的 5 项验证"建立你的基线档案，再回头补 01-03 的架构背景。
- **关键事实**：本篇所有集群/硬件数字以仓库根目录的 `FACTS.md` 为准（Stargate 口径、Llama 3 两套 24,576 GPU 集群、UALink 100 GB/s/端口、KV Cache 约 40 GiB 等）；引用前请自行核对官方来源。
- **注意常见误区**：CXL 不能扩展 GPU 显存（那是 NVLink-C2C 的事）；RTX 4090 没有 NVLink 也不支持 P2P；NVL72 必须液冷但 8 卡 B300 可以风冷。
