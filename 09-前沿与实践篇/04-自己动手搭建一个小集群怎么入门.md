# Q: 自己动手搭建一个小集群怎么入门？

## 为什么会有这个问题

到这一步，你读了 9 个篇章、40+ 篇文章——从芯片到网络、从并行策略到训练框架、从调度到运维。

你学到了"大型集群的设计原理"。但你可能最想做的是：**真的自己搭一个。**

一个 2-4 台机器的小集群，是理解所有这些概念的最佳方式。

## 解决什么问题

小集群让你可以在真实环境中"摸"到前面讲的所有概念：

- 亲手跑一次 NCCL All-Reduce → 理解通信开销
- 亲手配置 InfiniBand/RoCE → 理解网络拓扑
- 亲手装 CUDA + PyTorch → 理解依赖管理
- 亲手跑 FSDP/DeepSpeed → 理解分布式训练
- 亲手找个慢节点 → 理解 Straggler

### 先定预算和目标，再买硬件

```
目标定位（先想清楚你要学什么）：

入门版（数万元级）：
  目标：跑通 7B/8B 模型的微调，理解多卡通信
  2 台工作站，每台 1-2 张消费级/工作站级 GPU
    · RTX 4090（24GB）× 2-4
    · CPU：AMD Ryzen 9 / Intel i9
    · 内存：64-128 GB DDR5
    · 存储：2 TB NVMe + 4 TB HDD
    · 网络：万兆以太网（10GbE）起步，25GbE 更好
    · 系统：Ubuntu 22.04 LTS / Rocky Linux 9
  能做什么：QLoRA 微调 7B/8B、FSDP 实验、NCCL 通信测试
  不能做什么：别指望用消费级卡"训练 70B"（见下方误区）

进阶版（每台 8 卡 H100 服务器数十万美元级）：
  目标：生产级小集群，理解 IB 网络、调度、监控全栈
  2-4 台 8 卡服务器
    · GPU：H100/H200 SXM × 8/台
      （16 张 H100 总价约 $400K-700K 量级，报价随配置波动，
        建议多家询价，不要按某个精确数做预算）
    · CPU：双路 AMD EPYC / Intel Xeon
    · 内存：1-2 TB
    · 存储：NVMe × 4-8（本地缓存）+ 后端共享存储
    · 网络：每台 8×ConnectX-7（400G）+ NDR IB 交换机
    · 系统：Ubuntu 22.04 + Slurm

功耗预算（决定你家的电能不能带）：
  8×H100 服务器整机约 10-14 kW（GPU 5.6 kW + CPU/内存/网络/电源损耗）
  → 220V 单相电（~3.5 kW）完全不够，需要三相电或机房环境
  → 这是"进阶版"从家里搬到机房的最常见原因
```

### 选购要点（避开架构坑）

```
消费级卡的互联真相（很多人在这里花冤枉钱）：

  RTX 4090：
    · 没有 NVLink
    · 不支持 P2P（P2P over PCIe 被禁用）
    · 多卡通信全部走 PCIe → 经过主机内存中转
    → 多卡训练能用，但通信效率远低于数据中心卡

  RTX 6000 Ada（48GB）：
    · 也没有 NVLink（Ampere 时代的 RTX A6000 才有，
      Ada 一代取消了）
    · 优点是 48GB 大显存 + 做工可靠
    → 适合"显存敏感、通信不敏感"的单卡大模型推理/微调

  结论：想要卡间高速互联，只有 SXM 平台
  （A100/H100/H200/B 系列，NVLink 900 GB/s-1.8 TB/s 双向）。
  消费级多卡方案请按"通信走 PCIe"来设计你的并行策略：
  更适合 FSDP/ZeRO 这类"每步少量通信"的方案，
  而不是 TP 这种"每层高频通信"的方案。
```

### 最小采购清单

```
[入门版] 2 台工作站 + 2-4 张显卡
  1. 工作站：塔式工作站或自组（注意机箱散热和供电余量）
  2. 显卡：RTX 4090 × 2（预算够可上 RTX 6000 Ada 48GB）
  3. 存储：2 TB NVMe + 8 TB HDD
  4. 网络：25GbE 网卡（如 ConnectX-6 Lx）× 2 + 25GbE 交换机 × 1
  5. 电源：每卡按 450W TDP 预留，整机电源留 30% 余量

[进阶版] 2-4 台 8 卡服务器
  1. 服务器：主流 OEM 的 8×H100 SXM 机型（DGX 参考设计或同级）
  2. 网络：每台 8×400G（ConnectX-7 或 BlueField-3）+ NDR IB 交换机
     · 只有 2 台机器时，也可以 IB 直连（背对背），省一台交换机
     · 预算紧可考虑 RoCEv2（以太网交换机便宜得多），
       但要自己处理 PFC/ECN 无损配置（见第 03 网络篇）
  3. 存储：入门先用 NVMe + NFS 起步，数据量大了再上并行文件系统
     （Lustre / WEKA / GPFS，见第 04 存储篇）
```

### 开箱后的搭建步骤

```bash
# 0. 硬件连接
# ┌────────┐    25GbE/IB     ┌────────┐
# │ 机器 A │ ←────────────── → │ 机器 B │
# │ GPU0-3 │                  │ GPU4-7 │
# └────────┘                  └────────┘
#       ↓                        ↓
#    ┌──── 交换机 ────────────┐

# 1. 安装 Ubuntu Server
# 下载 Ubuntu 22.04 LTS Server ISO
# 用 Rufus 写入 USB，BIOS 设置为 UEFI 启动

# 2. 安装 NVIDIA 驱动和 CUDA
# 推荐用 NVIDIA 官方 runfile（更可控）
# 不要用 Ubuntu 仓库里的版本（太旧）
wget https://developer.download.nvidia.com/compute/cuda/12.4.0/local_installers/cuda_12.4.0_550.54.14_linux.run
sudo sh cuda_12.4.0_550.54.14_linux.run --toolkit --silent

# 验证
nvidia-smi      # 应该显示 GPU 列表
nvcc --version  # CUDA 12.4

# 3. 安装 PyTorch（自带 NCCL，不需要单独装 NCCL）
pip3 install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu124
```

### 开机后必做的 5 项验证

买硬件是一回事，**验证硬件真的按 advertised 性能在跑**是另一回事。每一步的输出都存档——它们是你未来排查问题的"基线"。

```bash
# 1. GPU 拓扑：确认 NVLink/PCIe 连接关系
nvidia-smi topo -m
# SXM 机器应该看到 GPU 两两之间是 NV#（NVLink）
# 消费级机器看到的是 PIX/PHB/SYS（PCIe 各级）
# 同时看清 GPU 和网卡（NIC）的亲和性——跨 NUMA 通信会变慢

# 2. 驱动/健康状态
nvidia-smi -q | grep -E "Driver Version|CUDA Version|ECC"

# 3. 网络带宽：IB 端口是否跑满
ibstat                          # 端口状态和速率（Rate 应为 400 for NDR）
ib_write_bw -d mlx5_0 --report_gbits  # 两台机器各跑一端，测 RDMA 带宽
# 单端口 NDR 应接近 400 Gb/s ≈ 50 GB/s；差得多就查线缆/固件

# 4. NCCL 集合通信基线（nccl-tests，需自行编译）
# git clone https://github.com/NVIDIA/nccl-tests && cd nccl-tests && make -j
./build/all_reduce_perf -b 8 -e 1G -f 2 -g 8     # 单机 8 卡
mpirun -np 16 -H node1:8,node2:8 ./build/all_reduce_perf -b 8 -e 1G -f 2
# 记录 busbw：单机 8×H200 NVLink 应 >400 GB/s；
# 跨机 NDR 每卡约 40-50 GB/s（受单端口 50 GB/s 限制）
# NCCL_DEBUG=INFO 可以看到 NCCL 识别到的拓扑和选择的算法/协议

# 5. 故障注入演练（现在出问题比训练中途出问题好）
# · 拔一根网线/光纤 → 确认 NCCL 报错信息和恢复流程
# · kill -9 一个 rank → 确认其余进程会正确退出而不是挂死
# · 限制一张卡（CUDA_VISIBLE_DEVICES）→ 确认调度和监控都能发现
```

**给每个测试建立基线档案**（日期、配置、busbw、温度），以后每次变更（换驱动、改 NCCL 版本、动网络）后重跑对比——带宽掉了 20% 你要当天知道，而不是三个月后。

## 小集群测试项目推荐

### 项目 1：跑通 FSDP2 + 8B 模型微调

目标：在 2 张 GPU 上对 Llama 3 8B 做 LoRA 微调（24GB 卡上用 QLoRA）

```bash
# 安装依赖
pip install transformers accelerate peft bitsandbytes

# 运行 FSDP2 微调
torchrun --nproc_per_node=2 \
  --master_port=29500 \
  fsdp_lora_train.py \
  --model_name meta-llama/Meta-Llama-3-8B \
  --batch_size 2 \
  --gradient_accumulation_steps 4
```

注意模型名：HuggingFace 上 Llama 3 8B 的模型卡是 `meta-llama/Meta-Llama-3-8B`（`meta-llama/Llama-3-7B` 不存在——Llama 3 没有 7B，最小是 8B）。

### 项目 2：跑 nccl-tests 对比不同拓扑的性能

```bash
# 单机内 2 卡性能
all_reduce_perf -b 8 -e 1G -f 2 -g 2

# 跨机 2 卡性能（关键测试！）
mpirun -np 2 -H node1:1,node2:1 ./build/all_reduce_perf -b 8 -e 1G -f 2 -g 1

# 对比：NVLink vs PCIe vs 网络
# 你会看到带宽的"断崖式"下降
# 想看 NCCL 选择了什么算法/协议：NCCL_DEBUG=INFO
```

### 项目 3：搭建最小 Slurm 集群

```bash
# 在 2 台机器上装 Slurm
# 控制节点（node1）：slurmctld
# 计算节点（node1, node2）：slurmd

# 配置 /etc/slurm/slurm.conf
cat > /etc/slurm/slurm.conf << 'EOF'
ClusterName=mini-cluster
ControlMachine=node1
SlurmUser=slurm
SlurmctldPort=6817
SlurmdPort=6818
AuthType=auth/munge
StateSaveLocation=/var/spool/slurmctld
SlurmdSpoolDir=/var/spool/slurmd
ProctrackType=proctrack/cgroup
ReturnToService=1

# 节点定义
NodeName=node1 CPUs=32 RealMemory=128000 Gres=gpu:rtx4090:2
NodeName=node2 CPUs=32 RealMemory=128000 Gres=gpu:rtx4090:2

# 分区定义
PartitionName=gpu Nodes=node1,node2 Default=YES MaxTime=48:00:00 State=UP
EOF

# 启动（注意服务名是 slurmd，没有 "dtld" 这个拼写）
systemctl start slurmctld
systemctl start slurmd

# 提交测试任务
sbatch --ntasks=2 --gpus=2 --wrap="torchrun --nproc_per_node=2 train.py"
```

### 项目 4：安装 DCGM + Prometheus + Grafana

```bash
# 安装 DCGM
apt-get install datacenter-gpu-manager
systemctl start nvidia-dcgm

# 安装 DCGM Exporter
docker run -d --gpus all --rm -p 9400:9400 nvidia/dcgm-exporter:latest

# 安装 Prometheus（docker-compose.yml）
cat > docker-compose.yml << 'EOF'
services:
  prometheus:
    image: prom/prometheus:latest
    ports: ["9090:9090"]
  grafana:
    image: grafana/grafana:latest
    ports: ["3000:3000"]
EOF

docker-compose up -d
```

## 🛠 常见故障排查

| 症状 | 可能原因 | 解决 |
|------|---------|------|
| `CUDA error: no kernel image is available` | PyTorch CUDA 版本不匹配 | `pip install torch --index-url ...` |
| `NCCL WARN: Connect to <IP> failed` | 防火墙阻塞了通信端口 | `ufw allow 29500` |
| `RuntimeError: NCCL error: unhandled system error` | IB 或 GDR 配置错误 | `NCCL_DEBUG=WARN` 查看具体错误 |
| 训练很慢 | NCCL 回退到了 NET/Socket（没用上 IB/NVLink） | `NCCL_DEBUG=INFO` 看是否出现 "NET/Socket"，检查 IB 驱动与拓扑 |
| cuda driver version insufficient | 驱动不够新 | `nvidia-smi` 看 Driver Version，升级 |
| file not found: libcuda.so | LD_LIBRARY_PATH 没设 | `export LD_LIBRARY_PATH=/usr/local/cuda/lib64:$LD_LIBRARY_PATH` |
