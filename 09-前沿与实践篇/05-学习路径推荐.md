# Q: 学习路径推荐

## 最后的问题

你已经读完了整个教程。从"为什么单卡不够"一直走到了"CXL 内存池化和全光互联"。

下一步是什么？如果你想把 AI 集群的知识从"知道"变成"能动手"，这条路径可以帮你走得远。

## 学习路径总览

```
┌──────────────┐
│ 理论（30%）   │ ← 本教程覆盖
├──────────────┤
│ 动手（40%）   │ ← 小集群 + 实验
├──────────────┤
│ 论文（15%）   │ ← 深入原理
├──────────────┤

```

## 第一阶段：巩固基础（1-2 周）

回顾本教程的 10 个篇章（00–09），确保你能用自己的话解释每个核心概念：

- [x] 为什么单卡不够用？数据并行 + All-Reduce 的原理
- [x] GPU 为什么比 CPU 快？NVLink 和 NVSwitch 的作用
- [x] InfiniBand 和 Ethernet 的本质区别
- [x] ZeRO-3 和 FSDP2 的区别和联系
- [x] TP/PP/SP/EP/DP 分别解决什么问题
- [x] MFU 和 GPU-Util 的区别

**推荐自测**：试着自己画出 70B 模型在 8 张 H100 上的训练时间线，标注出计算、通信、数据加载各占多少时间。

## 第二阶段：动手实践（3-6 周）

### 实验路线

**实验 1：单机多卡通信测试**
```bash
# 在单台 8 卡机器上测明白 NCCL 通信
all_reduce_perf -b 8 -e 8G -f 2 -g 8 2>&1 | tee results.log
# 理解 busbw/algbw 的区别
# 理解 NVLink 拓扑对通信的影响
```

**实验 2：小模型分布式训练**
```python
# 从 0 手写一个数据并行训练循环
# 不要用 DistributedDataParallel 封装
# 手动做 All-Reduce 梯度同步
# 理解"计算 → 通信 → 更新"的完整流程
```

**实验 3：FSDP2 对比实验**
```bash
# 在 2 张 GPU 上对比两种分片策略
# reshard_after_forward=True（全分片）vs reshard_after_forward=False（梯度+优化器分片）
# 记录每个策略的：显存占用、吞吐、通信开销
```

**实验 4：NCCL 调优实验**
```bash
# 修改每个环境变量，记录对性能的影响
for threads in 128 256 512 1024; do
  NCCL_NTHREADS=$threads all_reduce_perf -b 128M -e 128M -f 2 -g 8 | grep busbw
done
# 你会在自己机器上找到"最优参数"
```

**实验 5：搭建最小 Slurm 集群**
```bash
# 用 2 台机器搭建 Slurm 集群
# 配置 topology.conf（感知 NVLink 拓扑）
# 测试 Gang Scheduling（故意提交一个需要 4 台但只有 2 台的任务，看它怎么等）
```

**实验 6：Profiling 分析**
```bash
# 用 Nsight Systems 分析你的训练
nsys profile -o profile_output -t cuda,nvtx,nccl python train.py
# 找到"计算/通信比"
# 找到"最耗时的 kernel"
```

## 第三阶段：深入原理（4-8 周）

### 必读论文

按顺序阅读，每篇理解其核心思想：

| 论文 | 年份 | 领域 | 为什么重要 |
|------|------|------|-----------|
| **ZeRO**（Rajbhandari et al.）| 2020 | 显存优化 | ZeRO 三部曲的基础 |
| **Megatron-LM**（Shoeybi et al.）| 2019 | 模型并行 | TP 的原始论文 |
| **GPipe**（Huang et al.）| 2019 | 流水线并行 | PP 的基础思想 |
| **Ring Attention**（Liu et al.）| 2023 | 序列并行 | 长上下文的关键 |
| **FlashAttention**（Dao et al.）| 2022 | Attention 优化 | IO 感知的精确 Attention，长上下文和推理的必备基础 |
| **DeepSpeed-MoE**（Rajbhandari et al.）| 2022 | MoE 训练 | EP 的工程实践 |
| **FSDP**（Zhao et al.）| 2023 | PyTorch 分片 | FSDP 设计原理解析 |
| **Zero Bubble Pipeline Parallelism**（Qi et al.）| 2024 | 流水线并行 | 消除流水线气泡，提升 PP 效率 |
| **Guard**（MLSys 2026）| 2026 | 慢节点检测 | 部署在数万 GPU 前沿模型预训练上的实用检测方法 |

**再往上走一层**：想跟这个方向的前沿，盯这几个系统顶会——**OSDI / SOSP / NSDI / ASPLOS / SC**（AI 系统的工作大量发表在这几个会上，MLSys 相对更聚焦地覆盖训练/推理系统）。

**推理服务方向**还有一条独立的必读线：**vLLM 的 PagedAttention** 和 **SGLang 的 RadixAttention**。如果你更关心推理而不是训练，这两篇的优先级高于上面的 PP/ZeRO 系列。

## 第四阶段：工程实践（持续）

### 大项目推荐

**项目 1：为你的集群搭建完整的 Monitoring Stack**
```
要求：
  - DCGM Exporter 采集所有 GPU 指标
  - Prometheus 存储 30 天
  - Grafana 面板显示：MFU、GPU 利用率、NVLink 带宽、温度、功耗
  - 设置告警规则：GPU 温度 > 85°C、NVLink link down、显存使用 > 95%
```

**项目 2：自动化 NCCL 基准测试 CI**
```
要求：
  - 每次集群变更后自动跑 nccl-tests
  - 对比历史基线，发现 > 20% 的带宽下降就告警
  - 在 Grafana 上展示"Top-10 最慢节点"排名
```

**项目 3：实现一个自动扩缩容的训练服务**
```
要求：
  - 基于 Kueue/KAI Scheduler 实现
  - 训练任务在资源充足时自动调度
  - 推理服务在训练空闲时自动占用 GPU
  - 实现 Fair Scheduling 策略
```
