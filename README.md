---

## 🧭 本教程怎么读

这是一份**问答式**教程。每一节回答一个问题，遵循固定的六段式结构：

| 环节 | 作用 |
|------|------|
| **为什么诞生这个问题？** | 回到历史现场，当时卡在哪儿了 |
| **解决什么问题** | 它的核心贡献 |
| **优缺点** | 适用边界，不吹不黑 |
| **🛠 实操指南** | 落到手边的命令、配置与调参入口 |
| **对后续的铺垫** | 留下的新问题，引出下一节 |
| **参考资料** | 论文、白皮书与官方文档出处 |

**每节的结尾，就是下一节的起点。** 建议按序号顺序阅读，但每个问答也可以独立查阅。

## 🔗 因果链总览

本教程的核心理念是**技术是因问题而生的**。整个 AI 集群的故事可以浓缩为一条因果链：

```
单卡训练太慢
  → 问：为什么不用多卡？
    → 答：数据并行诞生 ← 需要做梯度同步 ([[01-基础篇/01-为什么单卡训练不够用]])
      → 问：梯度同步太慢怎么办？
        → 答：All-Reduce 算法 + NVLink 高速互联 ([[02-芯片篇/02-PCIe瓶颈与NVLink诞生]])
          → 问：模型太大一张卡放不下怎么办？
            → 答：张量并行 / 流水线并行 / ZeRO ([[05-并行策略篇/*]])
              → 问：多机之间怎么通信？
                → 答：InfiniBand / RoCEv2 + 网络拓扑 ([[03-网络篇/*]])
                  → 问：数据读取得跟上 GPU 速度
                    → 答：并行文件系统 + GPU Direct Storage ([[04-存储篇/*]])
                      → 问：几十台机器怎么高效管理？
                        → 答：Slurm / K8s 调度器 ([[07-调度篇/*]])
                          → 问：总有节点拖后腿怎么办？
                            → 答：慢节点检测 / Elastic Training ([[08-运维观测篇/*]])
                              → 问：业界怎么做的？未来方向？
                                → 答：超大集群 + 液冷 + CXL ([[09-前沿与实践篇/*]])
```
