# Q: 训练断了怎么办？

## 为什么会有这个问题

训练跑了 7 天，耗费了 512 张 H100 的 850,000 GPU 小时——折合云计算成本约 **$150,000**。

第 7 天晚上 3 点，集群电网波动，一台机器的电源模块烧了。训练进程全部崩溃。

**你失去的不仅是 7 天的训练进度，还有 $150,000 和两周的项目周期。**

这就是 Checkpoint（检查点）要解决的问题。

## 解决什么问题

Checkpoint 的核心功能：**在训练过程中定期保存模型的完整状态，训练崩溃后可以从最近的保存点恢复，而不是从头开始。**

### 没有 Checkpoint 的世界

```
Day 1  → Day 2  → Day 3  → ... → Day 7 → 💥崩溃
Start  10%      20%             70%    回到 0%
```

### 有 Checkpoint 的世界

```
Day 1  → Day 2  → Day 3  → ... → Day 7 → 💥崩溃 → 恢复到 Day 6 晚
Start  10%      20%             70%    回到 65% → 损失 0.5 天
```

### Checkpoint 里到底存了什么

```python
# 一个完整的 Checkpoint 包含
checkpoint = {
    "model_state_dict": model.state_dict(),  # 模型权重
    "optimizer_state_dict": optimizer.state_dict(),  # 优化器状态（Adam 动量和方差）
    "scheduler_state_dict": scheduler.state_dict(),  # 学习率调度器状态
    "epoch": current_epoch,
    "step": global_step,
    "loss": current_loss,
    "random_state": torch.random.get_rng_state(),  # 随机数状态（保证可复现）
    "data_loader_state": dataloader.state_dict(),  # 数据加载器位置
}
```

### 70B 模型的一个 Checkpoint 有多大？

```python
# 70B 参数 × 2 bytes（BF16）= 140 GB 权重
# 70B 参数 × 8 bytes（Adam FP32）= 560 GB 优化器状态
# 总计 ≈ 700 GB
# 
# 如果每 1 小时存一次 → 700 GB/h → 16.8 TB/天
# 这还只是一个任务！
```

### Checkpoint 的"隐形杀手"效应

Checkpoint 不但是"保险"，它本身就是一个**性能杀手**：

```
单次 Checkpoint 写入时间 = 700 GB / 写入带宽

假设写入带宽为 2 GB/s（WEKA 典型值）：
  700 GB / 2 GB/s = 350 秒 ≈ 6 分钟

如果每小时存一次 → 每 60 分钟里有 6 分钟在"空转"→ 10% 的 GPU 时间浪费
在 512 GPU 集群上：浪费 512 × 0.1 × 24h = 1,229 GPU 小时/天
```

**这就是所谓的 Checkpoint 开销——训练团队在"保险"和"效率"之间不断权衡。**

## 2026 年的 Checkpoint 策略

### 1. 异步 Checkpoint（推荐）

将 Checkpoint 写入操作卸载到后台线程，不让 GPU 等待：

```python
# 异步保存（训练不暂停）
import torch
import threading

class AsyncCheckpointer:
    def __init__(self, save_dir, interval_steps=1000):
        self.save_dir = save_dir
        self.interval = interval_steps
    
    def save(self, model, optimizer, step):
        if step % self.interval != 0:
            return
        
        # 先做"快照"（在 GPU 上复制 state_dict，很快）
        state = {
            'model': {k: v.clone() for k, v in model.state_dict().items()},
            'optimizer': optimizer.state_dict(),
            'step': step,
        }
        
        # 后台线程保存到磁盘（不阻塞训练）
        thread = threading.Thread(
            target=self._write_to_disk,
            args=(state, f'{self.save_dir}/checkpoint_{step}.pt')
        )
        thread.start()
    
    def _write_to_disk(self, state, path):
        torch.save(state, path)
```

### 2. 分布式 Checkpoint（DCP）

PyTorch 从 2.5 开始主推的分布式 Checkpoint——**每张卡只保存自己分片的那部分参数**：

```python
from torch.distributed.checkpoint import save, load
from torch.distributed.fsdp import FullyShardedDataParallel as FSDP

# 保存（无需集中收集所有参数）
save(
    state_dict={"model": model.state_dict()},
    storage_writer=torch.distributed.checkpoint.FileSystemWriter("/checkpoints/")
)

# 恢复
load(
    state_dict={"model": model.state_dict()},
    storage_reader=torch.distributed.checkpoint.FileSystemReader("/checkpoints/")
)
```

**DCP 的优势**：
- 每卡只保存自己的分片 → 写入量从 700 GB 降到 700/N GB
- 写入时间从 6 分钟降到 6/N 分钟
- 支持弹性 Checkpoint（节点数量发生变化时也能恢复）

### 3. 增量 Checkpoint

只保存自上次 Checkpoint 以来**发生变化**的参数：

```python
# 只保存梯度变化较大的层
for name, param in model.named_parameters():
    if param.grad is not None:
        grad_norm = param.grad.norm().item()
        if grad_norm > threshold:
            # 保存这一层
            incremental_state[name] = param.data.clone()
```

### 4. 分阶段 Checkpoint 策略

| 训练阶段 | 频率 | 保存量 | 理由 |
|---------|------|--------|------|
| 预热（前 500 step） | 每 100 step | 完整 | 这个阶段变化快，丢失代价高 |
| 正常训练 | 每 1000-5000 step | 完整 | 平衡保险和性能 |
| 收敛阶段 | 每 500 step | 完整 | 接近期望结果，不可丢失 |
| 日常恢复 | — | 最近的 3 个 | 防止"坏 Checkpoint" |

### ⚠️ 常见误区

- **误区**："Checkpoint 频率越高越好"
  - **实际**：Checkpoint 本身就是性能开销——频繁保存意味着更多的 GPU 时间被用在写入磁盘上。**推荐让 Checkpoint 开销不超过训练时间的 1-5%**。更实际的做法：找到"丢得起的最长训练时间"，然后把这个时间作为 Checkpoint 间隔。

- **误区**："分布式训练每张卡都要保存完整的 Checkpoint"
  - **实际**：FSDP/ZeRO-3 下每张卡只保存自己分片的那部分参数。**使用 DCP（分布式 Checkpoint）可以节省 N 倍的存储空间和写入时间**。不要用传统的 `torch.save(model.state_dict())` 做分布式 Checkpoint。

- **误区**："Checkpoint 保存完就安全了"
  - **实际**：**Checkpoint 在写入过程中可能损坏**（磁盘故障、网络中断）。保留最近 3-5 个 Checkpoint 并定期验证其完整性。更保险的做法：**保存后立即读取验证**。
