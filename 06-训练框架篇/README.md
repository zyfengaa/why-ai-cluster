# 训练框架篇 — 把并行策略落地

## 本篇章回答的问题

| Q&A | 核心链条 |
|------|---------|
| Q1: DeepSpeed ZeRO 系列在解决什么问题？ | 去除模型状态冗余：16 B/参数的账本，ZeRO-1/2/3 的 4×/8×/N× 递进（模型状态口径，激活另算） |
| Q2: ZeRO 和模型并行（TP/PP）是什么关系？ | 互补：ZeRO 分片模型状态，TP/PP 切计算；先算每卡预算再选并行 |
| Q3: Megatron-LM 为什么是"重装底盘"？ | TP 的每层 2 次 All-Reduce 范式，Megatron-Core（2023）与 TP+EP+CP+DP+PP 的 5D 并行 |
| Q4: FSDP2 为什么成为微调的默认选择？ | PyTorch 原生（fully_shard + DeviceMesh），per-parameter 分片，torch.compile/DCP 组合；生态迁移尚未完成 |
| Q5: 在实际场景中怎么选？ | 框架选型决策矩阵（每格附支持依据） |
| Q6: 混合精度训练（FP16/BF16/FP8/NVFP4）是怎么递进的？ | 精度格式的动态范围/尾数权衡；GEMM 峰值加速 ≠ 端到端加速 |
