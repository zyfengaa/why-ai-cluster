# Q: 混合精度训练（FP16/BF16/FP8）是怎么递进的？

## 为什么会有这个问题

训练大模型，精度和速度是一对天生的矛盾。FP32 最精确但显存消耗最大、计算最慢；FP16 快但动态范围不够；BF16 范围够了精度又不够……

业界花了 5 年时间，走了一条从"被迫降精度"到"主动降精度"的路。

## 解决什么问题

混合精度训练的核心目标：**在尽量不损失模型精度前提下，用更低的数值精度加速计算、节省显存。**

### 精度格式的演化

```
FP32（2012-2019）→ FP16 + Loss Scaling（2018）→ BF16（2020+）
→ FP8（2024+）→ NVFP4（2026 Blackwell）
```

| 格式 | 位宽 | 指数位 | 尾数位 | 动态范围 | 精度 | 硬件支持 |
|------|------|--------|--------|---------|------|---------|
| FP32 | 32 | 8 | 23 | ~10⁻⁸~10⁸ | 极高 | 所有 GPU |
| FP16 | 16 | 5 | 10 | ~10⁻⁵~10⁴ | 中 | 所有 GPU |
| BF16 | 16 | 8 | 7 | ~10⁻⁸~10⁸ | 中 | A100+ |
| FP8 E4M3 | 8 | 4 | 3 | ~10⁻²~10² | 低 | H100+ |
| FP8 E5M2 | 8 | 5 | 2 | ~10⁻⁴~10⁴ | 极低 | H100+ |
| NVFP4 | 4 | 3 | 1 | ~10⁻²~10² | 极低 | Blackwell 独占 |

**关键洞察**：FP16 和 BF16 谁更好？FP16 精度更高（10 bit 尾数 vs 7），但 BF16 范围更大（8 bit 指数 vs 5）。后者对训练更重要——**BF16 不需要 Loss Scaling 就能覆盖梯度的动态范围**，这就是它成为主流训练格式的原因。

### 为什么 FP32 不行了

```
70B 模型参数（FP32）：70B × 4 bytes = 280 GB
70B 模型参数（BF16）：70B × 2 bytes = 140 GB
加上优化器状态（Adam）：280 GB × 2 = 560 GB（FP32）
                      → 140 GB（BF16 参数）+ 280 GB（FP32 优化器状态）

结论：FP32 在 70B 模型上单卡需要 700+ GB 显存 → 不可能
      BF16 + ZeRO/FSDP → 8 张 H100 能装下
```

## 混合精度训练的演进

### 第一阶段：FP16 + Loss Scaling（2018-2020）

NVIDIA 和百度在 2018 年提出混合精度训练（Mixed Precision Training），核心做法：

```
1. 前向/反向用 FP16（快）
2. 主权重用 FP32 副本（精度不丢）
3. 损失缩放（Loss Scaling）：反向前把 loss 放大 2^K 倍，
   避免梯度在 FP16 下"消失"（超出 FP16 最小可表示范围）
4. 优化器更新在 FP32 上做
```

**痛点**：
- Loss Scaling 需要手动调——太大了梯度上溢，太小了下溢
- FP16 的 5 位指数覆盖不了梯度的分布范围

### 第二阶段：BF16 成为默认（2020-2024）

A100 引入 BF16，**指数位从 5 扩展到 8**，和 FP32 一样：

```
BF16 的优势：
  - 不需要 Loss Scaling（动态范围与 FP32 一致）
  - 训练稳定，不用操心精度溢出
  - 硬件 Tensor Core 速度与 FP16 一样快

BF16 的代价：
  - 尾数只有 7 bit，比 FP16 的 10 bit 少
  - 但实验证明：对训练收敛几乎无影响
```

**2024 年后的格局**：BF16 是训练的"默认精度"，FP32 只在 LayerNorm、Softmax 等数值敏感操作中使用。

### 第三阶段：FP8 训练（2024+）

H100 的 Transformer Engine 原生支持 FP8 计算，这是精度递进的关键一跳：

**FP8 的两种格式**：
- **E4M3**（4 指数 + 3 尾数）：用于前向（权重和激活值范围已知）
- **E5M2**（5 指数 + 2 尾数）：用于反向（梯度范围未知，需要更大动态范围）

**FP8 训练的实际做法**（2026 年生产最佳实践）：
```python
# 只在 Linear 层使用 FP8 Tensor Core
# LayerNorm、Dropout、激活函数、Softmax → 保持 BF16/FP32
# 这是经过验证的"黄金配方"
```

**实际加速比**：

| 配置 | 吞吐加速（vs BF16） | 精度损失 |
|------|-------------------|---------|
| BF16 baseline | 1× | 0% |
| FP8 E4M3（Linear 层） | 1.2-1.5× | ≈0% |
| MXFP8（Blackwell） | 1.32× | ≈0% |
| NVFP4（Blackwell） | 1.59-1.68× | 可控（需最后 4 层留 BF16）|

### 第四阶段：NVFP4 与 MXFP8（2026 Blackwell）

Blackwell 引入了两种新的精度格式：

**MXFP8（Block-Scale FP8）**：
- 每 32 个元素共享一个缩放因子（而非整个 tensor 一个）
- 更细粒度的量化 → 精度更好
- 在 Blackwell SM 上有硬件优化

**NVFP4（4-bit 浮点）**：
- 2026 年最重要的精度创新
- 单条 Tensor Core 指令原生执行（无需软件模拟）
- 吞吐提升 1.6-1.7×，微批次大小可翻倍

```
NVFP4 的训练要求：
  1. 最后 4 层保持在 BF16（称为 F0L4 策略）
  2. 优化器调参：AdamW ε=1e-8，lr 6e-4→6e-6
  3. Global batch size = 768（推荐）
  4. 全 NVFP4 模型会发散——最后几层对量化最敏感
```

## 🛠 实操指南

### 📋 决策指南：你该用哪种精度？

```
你的 GPU 型号？
├─ Blackwell（B200/GB300）→
│   ├─ 追求极致吞吐 → NVFP4（+60%），最后 4 层留 BF16
│   └─ 稳妥路线 → MXFP8（+32%），零代码修改
│
├─ Hopper（H100/H200）→
│   └─ FP8 E4M3（+20-50%），Transformer Engine 自动处理
│       └─ 注意：只在 Linear 层用 FP8，其他层 BF16
│
└─ Ampere（A100）→
    └─ BF16（默认），不需要 Loss Scaling
         └─ 显存不够再考虑 FP16 + Loss Scaling
```

```python
# 精度选择的简化判断
gpu_capability = "blackwell"  # 根据实际情况填写
model_size = 70  # 模型参数量（B）
precision_budget = {
    "fp32": 16,   # bytes per param（参数+梯度+优化器状态）
    "bf16": 8,
    "fp8": 4,
    "nvfp4": 2,
}
gpu_memory = 80  # H100 显存（GB）
n_gpus = 8

for prec, bytes_per_param in precision_budget.items():
    total_mem = model_size * 1e9 * bytes_per_param / (1024**3)
    per_gpu = total_mem / n_gpus
    print(f"{prec}: {per_gpu:.1f} GB/卡 {'✅' if per_gpu < gpu_memory else '❌'}")
```

import time

for dtype in [torch.float32, torch.float16, torch.bfloat16]:
    try:
        x = torch.randn(4096, 4096, device='cuda', dtype=dtype)
        w = torch.randn(4096, 4096, device='cuda', dtype=dtype)
        
        # 预热
        for _ in range(100):
            torch.mm(x, w)
        torch.cuda.synchronize()
        
        # 计时
        start = time.time()
        for _ in range(1000):
            torch.mm(x, w)

### ⚠️ 常见误区

- **误区**："FP16 和 BF16 是一样的"
  - **实际**：FP16 精度更高（10 位尾数），但 BF16 范围更大（8 位指数）。对训练而言，**范围比精度更重要**——BF16 不需要 Loss Scaling，训练稳定得多。

- **误区**："FP8 训练一定会损失精度"
  - **实际**：2026 年的最佳实践证明，FP8 只用在 Linear 层的 GEMM 计算上，其他层保持 BF16，可以做到**零精度损失**。NVIDIA 内部和外部的 1T+ token 实验都验证了这一点。

- **误区**："NVFP4 就是 4-bit 量化，可以闭眼用"
  - **实际**：NVFP4 需要**精细的调参策略**——最后 4 层必须在 BF16，优化器参数需要调整，batch size 也有要求。不加注意直接使用会导致模型发散。

- **误区**："精度越低越好，反正训练完可以转回高精度"
  - **实际**：训练和推理的精度需求不同。训练时梯度累积误差可能被放大多个 step，低精度训练需要仔细验证收敛性。**NVFP4 目前只在 1T+ token 的大规模实验中验证过，小规模微调可能得不偿失。**

### 📊 底线数字速查

| 精度格式 | 速度提升（vs BF16） | 显存节省 | 精度风险 | 硬件要求 |
|---------|-------------------|---------|---------|---------|
| BF16 | baseline | baseline | 无 | A100+ |
| FP16 | ~1× | ~1× | 需 Loss Scaling | 所有 GPU |
| FP8 E4M3 | **1.2-1.5×** | **~2×** | 极低 | H100+ |
| MXFP8 | **1.32×** | ~2× | 极低 | B200+ |
| NVFP4 | **1.59-1.68×** | **~4×** | 可控 | GB300+ |

**一键决策**：A100 用 BF16，H100 用 FP8（Linear 层），Blackwell 追吞吐用 NVFP4 求稳妥用 MXFP8。

### 💡 一句话记住

> **"混合精度训练走了一条'降维不降效'的路：BF16 用更少的位宽覆盖了 FP32 的动态范围，FP8 用硬件加速做到了零精度损失，NVFP4 用 4 bit 把吞吐翻倍——但代价是需要精细的稳定性策略。2026 年的铁律是：能用 BF16 绝对不用 FP32，能用 FP8 试试就试试，NVFP4 留给有经验的团队。"**
