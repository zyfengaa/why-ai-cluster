# Q: 在实际场景中怎么选？— 2026 年框架选型决策矩阵

## 为什么会有这个问题

现在你了解了三个主要框架的各自定位：

| 框架 | 一句话 | 最强项 |
|------|--------|--------|
| **FSDP2** | PyTorch 原生，最简单 | 微调 + 中小模型 |
| **DeepSpeed** | 微软出品，功能最全 | 内存受限 + 长上下文 + MoE |
| **Megatron-Core** | NVIDIA 工业级，性能最高 | 超大模型预训练 |

但实际项目不会只用"最好的框架"——你需要根据场景做选择。

## 2026 年选型决策树

```
第一步：你的模型规模有多大？
│
├─ < 7B（单卡能装下）
│   └→ DDP，或 FSDP2 不调 `fully_shard`（等价于不做分片）
│
├─ 7B - 34B（单机 8 卡基本能装）
│   └→ FSDP2 全分片（`reshard_after_forward=True`，首选，API 最简洁）
│      └→ 需要长上下文（> 32K）？→ Context Parallel（CP）；DeepSpeed-Ulysses 是其中一种实现（要求 head 数能被 SP 度整除）
│
├─ 34B - 70B（多节点必须）
│   └→ FSDP2 全分片（`reshard_after_forward=True`）；只有**单层 hidden 放不下**时才叠加 TP=8（需 2D mesh `(tp, fsdp)`）
│      └→ 显存极度紧张？→ DeepSpeed ZeRO-3 + CPU Offload
│
└─ > 70B（百亿级预训练）
    └→ Megatron-Core（TP+PP+DP+CP+EP 5D 并行）
       └→ MoE 模型？→ Megatron-Core MoE 或 DeepSpeed-MoE

第二步：你的场景是？
│
├─ 微调（Fine-tuning）
│   └→ FSDP2（简单、生态好、支持 LoRA）
│
├─ 全量微调（Full fine-tune）
│   └→ FSDP2 + TP（70B 以下）或 Megatron-Core（70B 以上）
│
├─ 预训练（Pre-training from scratch）
│   └→ 70B+ → Megatron-Core（稳定、MFU 最高）
│   └→ < 70B → FSDP2 或 DeepSpeed ZeRO-3
│
└─ 研究/实验
    └→ FSDP2（快速迭代，不锁死在特定框架）
```

---

## 各场景的详细推荐

### 场景 1：LoRA 微调 7B-13B 模型

| 维度 | 推荐 |
|------|------|
| 框架 | **FSDP2 + PEFT** |
| 配置 | `reshard_after_forward=False`（梯度+优化器分片），显存充裕时也可不分片 |
| GPU | 1-8 卡 |
| 理由 | 最简单，HuggingFace PEFT 原生集成 |
| 代码量 | 3 行修改 |

### 场景 2：全量微调 34B-70B 模型

| 维度 | 推荐 |
|------|------|
| 框架 | **FSDP2（全分片）** |
| 配置 | `reshard_after_forward=True` + TP=8（如果单层大） |
| GPU | 8-64 卡 |
| 理由 | API 简洁，torch.compile 加速 |
| 预期 MFU | 40-55% |

### 场景 3：长上下文训练（> 32K tokens）

| 维度 | 推荐 |
|------|------|
| 框架 | **Context Parallel（CP）**：Megatron-Core CP、FSDP2 + CP，或 DeepSpeed-Ulysses |
| 理由 | 2026 年长上下文的主流答案是 CP（沿序列维切分）；Ulysses 是其中一种实现，且**要求 head 数能被 SP 度整除** |
| 注意 | Ulysses 自动处理序列切分，与 ZeRO-3 兼容 |

### 场景 4：70B+ 模型预训练

| 维度 | 推荐 |
|------|------|
| 框架 | **Megatron-Core + NeMo** |
| 配置 | TP=8, PP=4-8, DP=4-16, SP=（可选） |
| GPU | 128-1024 卡 |
| 理由 | 工业级稳定，MFU 最高（45-55%） |
| 学习成本 | 高 |

### 场景 5：MoE 模型训练

| 维度 | 推荐 |
|------|------|
| 框架 | **Megatron-Core MoE** 或 **DeepSpeed-MoE** |
| 理由 | FSDP2 的 EP 支持正在成形（TorchTitan 已验证），但通用 tp2ep 折叠与 ETP 尚未支持，生产 MoE 仍首选这两个框架 |
| 选择 | Megatron + EP 性能更优，DeepSpeed 配置更灵活 |

### 场景 6：研究/快速实验

| 维度 | 推荐 |
|------|------|
| 框架 | **FSDP2 + torch.compile** |
| 理由 | 不锁死在特定框架，代码可移植 |
| 工具 | HuggingFace Accelerate + FSDP2 |

## 框架兼容性速查

| 需求 | FSDP2 | DeepSpeed | Megatron-Core |
|------|-------|-----------|---------------|
| PyTorch 原生 | ✅ 原生 | ⚠️ 外部依赖 | ❌ 完全独立 |
| HuggingFace | ✅ 原生 | ✅ 深度集成 | ❌ 需要转换 |
| torch.compile | ✅ 兼容 | ⚠️ 部分兼容（DeepCompile） | ⚠️ 部分兼容 |
| FP8 训练 | ⚠️ torch.compile | ❌ | ✅ Transformer Engine |
| LoRA 支持 | ✅ PEFT 集成 | ✅ DeepSpeed-LoRA | ❌ |
| CPU Offload | ⚠️ 基本 | ✅ ZeRO-Infinity | ❌ |
| NVMe Offload | ❌ | ✅ 唯一方案 | ❌ |
| MoE | ⚠️ EP 支持成形中（TorchTitan 已验证） | ✅ DeepSpeed-MoE | ✅ Megatron-EP |
| 长上下文 | ⚠️ 有限 | ✅ Ulysses | ✅ Megatron-CP |
| 弹性训练 | ✅ DCP | ❌ | ⚠️ 有限 |
| 优化器 | ✅ 任意 `torch.optim`（AdamW / Adafactor），8-bit 需 bitsandbytes | ✅ 内置 DeepSpeedCPUAdam、1-bit Adam/AdamW，8-bit 支持好 | ⚠️ 需按 Megatron 规范选 `--optimizer`（adam / fused_adam），自定义优化器要适配 |
