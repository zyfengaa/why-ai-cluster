# Q: 在实际场景中怎么选？— 框架选型决策矩阵

## 为什么会有这个问题

现在你了解了三个主要框架的各自定位：

| 框架 | 一句话 | 最强项 |
|------|--------|--------|
| **FSDP2** | PyTorch 原生，最简单 | 微调 + 中小模型 |
| **DeepSpeed** | 微软出品，功能最全 | 内存受限 + 长上下文 + MoE |
| **Megatron-Core** | NVIDIA 工业级，性能最高 | 超大模型预训练 |

但实际项目不会只用"最好的框架"——你需要根据场景做选择。

## 选型决策树

参数规模先统一口径：7B 是**十亿级**（10⁹）、70B 是**千亿级**（10¹¹）、405B 也是千亿级、1T+ 是**万亿级**（10¹²）。

```
第一步：你的模型规模有多大？
│
├─ < 7B（完整训练状态 16 B/参数 < 112 GB，分片后单机可放）
│   └→ DDP 或 FSDP2（最简单）
│
├─ 7B - 34B（完整训练状态 112-544 GB）
│   └→ FSDP2 FULL_SHARD 或 DeepSpeed ZeRO-2/3（首选，API 简洁）
│      └→ 需要长上下文（> 32K）？→ DeepSpeed-Ulysses 或 Megatron SP/CP
│
├─ 34B - 70B（完整训练状态 0.5-1.12 TB，多节点常态）
│   └→ FSDP2/ZeRO-3 + TP 组合，或 Megatron（TP=8 + DP-ZeRO）
│      └→ 显存极度紧张？→ DeepSpeed ZeRO-3 + CPU Offload（接受吞吐损失）
│
└─ > 70B（千亿级到万亿级预训练）
    └→ Megatron-Core（TP+PP+CP+EP+DP 5D 并行）
       └→ MoE 模型？→ Megatron-Core MoE 或 DeepSpeed-MoE

第二步：你的场景是？
│
├─ LoRA/PEFT 微调
│   └→ HF PEFT + FSDP2/DeepSpeed（生态最成熟）
│
├─ 全量微调（Full fine-tune）
│   └→ FSDP2 + 可选 TP（70B 以下）或 Megatron-Core（70B 以上）
│
├─ 预训练（Pre-training from scratch）
│   └→ 千亿级以上 → Megatron-Core（稳定、MFU 高）
│   └→ 百亿级以下 → FSDP2 或 DeepSpeed ZeRO-2/3
│
└─ 研究/实验
    └→ FSDP2（快速迭代，不锁死在特定框架）
```

## 各场景的详细推荐

### 场景 1：LoRA 微调 7B-13B 模型

| 维度 | 推荐 |
|------|------|
| 框架 | **HF PEFT + FSDP2 或 DeepSpeed** |
| 配置 | LoRA 参数量小，常规模分片压力低（FSDP2 或 ZeRO-1/2 即可） |
| GPU | 1-8 卡 |
| 理由 | HF PEFT 生态最成熟，与两个框架都有官方集成 |

### 场景 2：全量微调 34B-70B 模型

| 维度 | 推荐 |
|------|------|
| 框架 | **FSDP2 FULL_SHARD 或 DeepSpeed ZeRO-3** |
| 配置 | 单层大时加 TP（FSDP2 经 DeviceMesh 与 TP 组合，见 TorchTitan） |
| GPU | 8-64 卡 |
| 理由 | 70B 完整训练状态约 1.12 TB，必须分片；微调 batch 小，激活相对可控 |

### 场景 3：长上下文训练（> 32K tokens）

| 维度 | 推荐 |
|------|------|
| 框架 | **DeepSpeed-Ulysses** 或 **Megatron SP/CP** |
| 理由 | 序列并行把激活按序列维切开；FSDP2 本身不分片激活，需配合激活重计算 |

### 场景 4：70B+ 模型预训练

| 维度 | 推荐 |
|------|------|
| 框架 | **Megatron-Core（可经 NeMo/Megatron-Bridge 使用）** |
| 配置 | TP=8（NVLink 域内）+ PP + CP + DP（ZeRO-1/2），MoE 加 EP |
| GPU | 数百到数万卡 |
| 理由 | TP 层内通信要求高带宽域；PP/CP/EP 是 Megatron 原生组合 |

### 场景 5：MoE 模型训练

| 维度 | 推荐 |
|------|------|
| 框架 | **Megatron-Core MoE** 或 **DeepSpeed-MoE** |
| 理由 | EP 不是 FSDP2 的核心能力，MoE 专家并行这两家最成熟 |
| 选择 | Megatron 的 EP 与 5D 并行组合更完整（arXiv:2504.14960），DeepSpeed 配置门槛更低 |

### 场景 6：研究/快速实验

| 维度 | 推荐 |
|------|------|
| 框架 | **FSDP2 + torch.compile** |
| 理由 | 不锁死在特定框架，代码可移植 |
| 工具 | HF Accelerate / TorchTitan |

### 场景 7：RLHF / GRPO

| 维度 | 推荐 |
|------|------|
| 框架 | **verl / OpenRLHF / TRL**（小规模） |
| 并行 | rollout 引擎：TP=8 + 大批量；训练引擎：FSDP/PP + TP |
| 关键 | **权重重分片**（训练完的权重转成推理引擎的切分）、colocate、异步 rollout、reward model 的显存 |
| 不建议 | 直接用预训练框架硬拼 rollout；两套引擎的并行模型不同，硬拼会两头不讨好 |

### 场景 8：知识蒸馏

| 维度 | 推荐 |
|------|------|
| 框架 | 教师侧用推理引擎（vLLM/SGLang/TensorRT-LLM）；学生侧用 FSDP2/DeepSpeed/Megatron |
| 并行 | 教师 TP（+PP/EP）；学生按 16 B/参数配 DP/FSDP/3D |
| 关键 | **logits 带宽**（B×S×V）、top-k logits、同卡/同节点 colocate、或离线生成蒸馏数据 |
| 不建议 | 教师和学生共用一套并行配置——两者账本不同 |

### 场景 9：多 LoRA 服务

| 维度 | 推荐 |
|------|------|
| 训练 | HF PEFT + FSDP2/DeepSpeed（8B–70B） |
| 服务 | vLLM / S-LoRA / Punica 等多适配器方案 |
| 关键 | 底座权重共享、适配器热加载、按请求路由到对应 adapter |
| 注意 | 训练侧的 LoRA 并行方案和服务侧的批处理/路由是两件事 |

### 2026 年的框架版图（补充）

| 框架 | 定位 | 适合 |
|------|------|------|
| **TorchTitan** | PyTorch 官方 FSDP2 + TP + PP + float8 参考实现 | 想用原生栈复现 3D 并行 |
| **NeMo / Megatron-Bridge** | Megatron-Core 的易用封装 | 想要 Megatron 性能但不想手写并行 |
| **verl** | RL 训练框架（rollout + 训练 + reshard） | GRPO/PPO 生产 |
| **OpenRLHF** | RLHF/RL 训练框架 | 中小规模 RL |
| **Ray Train** | 分布式编排层 | 多框架统一调度 |
| **SkyPilot** | 跨云/跨集群作业编排 | 多云或混合云 |

选型原则没变：**先按"模型状态 ÷ 分片后每卡显存"选并行，再按"要不要 RL/蒸馏/多 LoRA"选框架**。不要因为某个框架流行就倒过来选。

## 框架兼容性速查（每格附依据）

| 需求 | FSDP2 | DeepSpeed | Megatron-Core |
|------|-------|-----------|---------------|
| PyTorch 原生 | ✅ 内置于 PyTorch | ⚠️ 独立库（pip install deepspeed） | ⚠️ 独立库（pip install megatron-core） |
| HuggingFace 集成 | ✅ Transformers 支持 FSDP2/FSDP1 | ✅ 长期深度集成 | ⚠️ 需经 NeMo/Megatron-Bridge，或格式转换 |
| torch.compile | ✅ 原生兼容（FSDP2 重写的主要动机） | ⚠️ 有限 | ⚠️ 逐步支持中 |
| FP8 训练 | ⚠️ 需 Transformer Engine / torchao 叠加 | ✅ 支持（经 Transformer Engine 集成） | ✅ 原生 TE 集成（--fp8-format） |
| LoRA/PEFT | ✅ HF PEFT 集成 | ✅ DeepSpeed 内置 LoRA | ⚠️ 核心不含，需 NeMo/Megatron-Bridge 的 PEFT 或第三方 |
| CPU Offload | ⚠️ 实验性/有限（FSDP1 有 CPUOffload，FSDP2 支持仍在完善） | ✅ ZeRO-Offload/Infinity 最成熟 | ⚠️ 核心不含，靠周边方案 |
| NVMe Offload | ❌ 无原生支持 | ✅ ZeRO-Infinity（独有级成熟度） | ❌ 无原生支持 |
| MoE / EP | ❌ EP 非核心能力，需组合其他方案 | ✅ DeepSpeed-MoE | ✅ 原生 EP + 5D 组合 |
| 长上下文 / 序列并行 | ⚠️ 需激活重计算或外部 SP | ✅ Ulysses + Ring Attention | ✅ Megatron-SP + CP |
| 弹性训练（容错缩扩容） | ⚠️ DCP 支持拓扑变化恢复 checkpoint | ⚠️ 支持（基于 torch elastic 的弹性方案） | ⚠️ 有限 |

> 图例：✅ 原生/官方支持；⚠️ 部分支持或需插件、集成层；❌ 无原生支持。FP8 一行的依据：DeepSpeed 与 Megatron 都通过 NVIDIA Transformer Engine 获得 FP8 能力，FSDP2 需要用户自行叠加 TE 或 torchao。

## 💡 一句话记住

> **"选框架先算两笔账：完整训练状态（16 B/参数）分片后每卡放多少、单层计算切分后放多少。微调用 FSDP2，内存受限找 DeepSpeed，千亿级以上预训练上 Megatron——MoE/长上下文/卸载这些特殊需求，按上面的兼容表逐格核对，别把'部分支持'当'原生支持'用。"**
