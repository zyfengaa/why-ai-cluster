# Q: 为什么 GPU 显存这么贵？不能像内存一样加条子吗？

## 为什么会有这个问题

一台服务器可以插 1TB DDR5 内存，价格也就几千块。但一张 80GB HBM 的 GPU，要多花上万美元。都是"内存"，为什么差距这么大？

## 解决什么问题：HBM 的制造秘密

GPU 用的显存叫 **HBM（High Bandwidth Memory，高带宽内存）**，和普通 DDR 内存是两种完全不同的东西。

### 物理结构对比

```
DDR5 内存条：                    HBM 显存堆栈：
┌─────────────────────┐         ┌─────────────────┐
│  DDR5 芯片 × 8颗    │         │   逻辑控制层     │ ← 最底层
│  各自独立封装         │         ├─────────────────┤
│  插在主板 DIMM 槽上  │         │   DRAM 层 4     │
└─────────────────────┘         ├─────────────────┤
                                 │   DRAM 层 3     │
                                 ├─────────────────┤
                                 │   DRAM 层 2     │
                                 ├─────────────────┤
                                 │   DRAM 层 1     │
                                 └─────────────────┘
                              通过硅通孔（TSV）垂直互联
```

关键差异：

| 特性 | DDR5 | HBM3/HBM3e |
|------|------|-----------|
| 封装方式 | 独立芯片插在主板上 | 3D 堆叠，通过**硅中介层**和 GPU 封装在一起 |
| 位宽 | 64 bit（单条） | **1,024 bit**（是 DDR 的 16 倍） |
| 带宽 | 64 GB/s（DDR5-6400） | **3,350 GB/s**（H100 HBM3） |
| 每 GB 成本 | ~$5 | **约 $10-20（公开估算，随世代/容量/合约期变化，不作精确承诺）** |
| 最大容量/颗 | ~256 GB | 16-36 GB/堆栈（随世代提升） |

### 为什么 HBM 带宽这么高？

关键在**总线宽度**。DDR5 一条通道 64 bit，而 HBM3 每堆栈 **1,024 bit 位宽**——同样是 1 秒钟，HBM 一次能搬进 16 倍的数据。

打个比方：
- DDR5：单车道，但跑得快（频率高）
- HBM3：16 车道，就算跑得慢点，总吞吐也碾压

### 为什么 HBM 这么贵？

1. **3D 堆叠工艺复杂**：要把 8-12 层 DRAM 芯片堆在一起，层之间用硅通孔（TSV）穿透连接，良率极难控制
2. **封装成本高**：HBM 必须和 GPU 封装在同一块基板上，通过硅中介层（Interposer）互联，这需要 CoWoS（Chip-on-Wafer-on-Substrate）封装技术，近年产能长期紧张
3. **容量限制**：每堆栈容量有限（HBM3 约 16-24 GB、HBM3e 可到 36 GB），GB300 要达到 288 GB 需要 8 个堆栈（8 × 36 GB）同时工作

## 为什么不能像 DDR 那样随意加容量？

一个 GPU 核心周围的空间是固定的，能放的 HBM 堆栈数量有限：

| GPU | HBM 堆栈数 | 总显存 | 总位宽 |
|-----|-----------|--------|------|
| A100 80GB | **5** | 80 GB（5 × 16 GB） | **5,120 bit**（5 × 1,024） |
| H100 80GB | **5** | 80 GB HBM3（5 × 16 GB） | **5,120 bit** |
| B200 | 8 | 192 GB HBM3e（8 × 24 GB） | 8,192 bit |
| **GB300** | **8** | **288 GB HBM3e（8 × 36 GB）** | **8,192 bit** |

> 注意：**A100/H100 80GB 都是 5 个堆栈、5,120-bit，不是 6 个**。所谓"6 堆栈"常见于早期传闻或与 HBM2 时代的 V100（4 堆栈）混淆。

要增加容量，要么：
- 加更多 HBM 堆栈 → 但 GPU 芯片面积有限，CoWoS 封装成本飙升
- 用更高密度的 HBM → 每堆栈从 16 GB 到 24 GB 到 36 GB，层数增多（8-Hi → 12-Hi → 16-Hi），良率逐步下降

这也是为什么 Blackwell 花了很大精力做 **NVLink 显存池化**——在 NVLink 域内把多张 GPU 的显存合并为一个更大的逻辑显存池。

## 🛠 实操指南

### 📋 决策指南：你需要多少显存？预算怎么分配？

**先算显存需求，再决定买哪代 GPU（口径：GB 按十进制，训练状态 = 16 B/参数）：**

```python
# 显存需求估算公式
模型参数量(B) × 精度字节 × (1 + 优化器系数 + 梯度系数) + 激活值

# 实际数字（以 70B 为例）：
# 仅 BF16 权重：70 × 2 = 140 GB
# 完整训练状态（16 B/参数）：
#   BF16 权重 140 + BF16 梯度 140 + FP32 master 280 + Adam m/v 560
#   = 约 1.12 TB → 需要 8×H100 以上（还要另加激活值）
# 仅权重 + 优化器（14 B/参数）：约 980 GB
#
# LoRA 微调 70B（BF16）:
#   140 GB（权重）+ 少量 LoRA 权重 + 少量优化器状态 ≈ 150-200 GB
#   → 1×GB300（288 GB）就够了
#
# 推理 70B（BF16）:
#   140 GB（权重）→ 2×H100 NVL（94 GB/卡，双卡 188 GB）
#   或 2×H100 SXM（80 GB/卡，160 GB）
```

**显存成本估算（公开估算值，随世代/容量/采购规模波动大，不作精确承诺）：**

| GPU | 显存总容量 | 显存类型 | 每 GB 成本（估算） |
|-----|-----------|---------|-----------------|
| H100 SXM | 80 GB HBM3 | HBM3 | 约 $10-20 |
| H200 SXM | 141 GB HBM3e | HBM3e | 约 $10-20 |
| B200 | 192 GB HBM3e | HBM3e | 约 $10-20 |
| MI300X | 192 GB HBM3 | HBM3 | 约 $10-20 |
| GB300 | 288 GB HBM3e | HBM3e | 约 $10-20 |

**一条经验**：显存成本在高端 GPU BOM 中的占比随代际持续上升（HBM3e 时代已占相当比例，各家拆解口径不一）。这意味着**未来 GPU 的价差主要来自显存大小，而不是算力**。具体占比请参考你采购批次的实际报价，不要套用任何精确百分比。

### 🔧 自己动手验：你的训练任务到底吃多少显存？

```bash
# 1. 最简单的检查：训练过程中看显存占用
nvidia-smi --query-gpu=name,memory.used,memory.total --format=csv -l 5
# 在训练启动后观察显存峰值（通常在前几个 step 达到）
# 注意：memory.total 是显存容量，nvidia-smi 的 utilization 字段是带宽利用率，不是容量占用

# 2. 用 PyTorch 的 memory 统计定位谁在吃显存
python -c "
import torch

# 模拟一个 7B 模型
model = torch.nn.Linear(4096, 4096)
print(f'模型参数: {sum(p.numel() for p in model.parameters())/1e9:.2f}B')

# 查看显存分配
print(f'已分配: {torch.cuda.memory_allocated()/1024**3:.1f} GB')
print(f'缓存: {torch.cuda.memory_reserved()/1024**3:.1f} GB')
print(f'峰值: {torch.cuda.max_memory_allocated()/1024**3:.1f} GB')
"

# 3. 最精确：用 Nsight Systems 看显存分配
nsys profile --trace=cuda,nvtx python train.py
# 然后在 GUI 里看 Memory 时间线，找到峰值
```

### ⚠️ 常见误区

- **误区**："HBM 和 DDR 都是内存，HBM 贵只是因为 NVIDIA 想多赚钱"
  - **实际**：HBM 的制造工艺比 DDR 复杂得多——**3D 堆叠需要硅通孔（TSV）穿透 8-12 层 DRAM 芯片**，良率控制极其困难。HBM 每 GB 价格通常是同期 DDR5 的数倍，且随世代与供需波动（公开估算约 $10-20/GB，不作精确承诺）。HBM 还需要和 GPU 通过 CoWoS 封装在一起，先进封装产能近年一直紧张。

- **误区**："显存不够可以加，就像 DDR 内存条一样插几根"
  - **实际**：GPU 核心周围的空间是固定的，能放的 HBM 堆栈数量上限由**芯片面积和 CoWoS reticle 限制**决定。A100/H100 80GB 是 5 堆栈封顶，B200/GB300 是 8 堆栈。要在不增加堆栈数的情况下提升容量，只能靠每堆栈的密度（8-Hi → 12-Hi → 16-Hi），而密度提升意味着良率下降、成本上升。

- **误区**："显存越大的 GPU 性价比越高"
  - **实际**：显存是大头，但**只为用得上的容量付费**。如果你不需要 288 GB（比如只做推理，70B BF16 权重 140 GB 就够了），H200（141 GB）或 2×H100 NVL（188 GB）可能是更划算的选择。**不要为用不上的显存付费。**

### 💡 一句话记住

> **"HBM 不是普通的'内存条'——它是 8 到 12 层 DRAM 堆起来的 3D 摩天大楼，每层之间用针尖大小的孔穿透连接。这就是为什么它又快又贵又少。"**
