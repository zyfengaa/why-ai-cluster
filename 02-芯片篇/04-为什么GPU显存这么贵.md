# Q: 为什么 GPU 显存这么贵？不能像内存一样加条子吗？

## 为什么会有这个问题

一台服务器可以插 1TB DDR5 内存，价格也就几千块。但一张 80GB HBM 的 GPU，要多花上万美元。都是"内存"，为什么差距这么大？

## 解决什么问题：HBM 的制造秘密

GPU 用的显存叫 **HBM（High Bandwidth Memory，高带宽内存）**，和普通 DDR 内存是两种完全不同的东西。

### 物理结构对比

```
DDR5 内存条：                    HBM 显存堆栈：
┌─────────────────────┐         ┌─────────────────┐
│  DDR5 芯片 × 8颗    │         │   逻辑控制层     │ ← 最底层
│  各自独立封装         │         ├─────────────────┤
│  插在主板 DIMM 槽上  │         │   DRAM 层 4     │
└─────────────────────┘         ├─────────────────┤
                                 │   DRAM 层 3     │
                                 ├─────────────────┤
                                 │   DRAM 层 2     │
                                 ├─────────────────┤
                                 │   DRAM 层 1     │
                                 └─────────────────┘
                              通过硅通孔（TSV）垂直互联
```

关键差异：

| 特性 | DDR5 | HBM3/HBM3e |
|------|------|-----------|
| 封装方式 | 独立芯片插在主板上 | 3D 堆叠，通过**硅中介层**和 GPU 封装在一起 |
| 位宽 | 64 bit（单条） | **1,024 bit**（是 DDR 的 16 倍） |
| 带宽 | 64 GB/s（DDR5-6400） | **3,350 GB/s**（H100 HBM3） |
| 每 GB 成本 | ~$5-10 | ~$30-50 |
| 最大容量/颗 | ~256 GB | 24-36 GB/堆栈 |

### 为什么 HBM 带宽这么高？

关键在**总线宽度**。DDR5 一条通道 64 bit，而 HBM3 有 **1,024 bit 位宽**——同样是 1 秒钟，HBM 一次能搬进 16 倍的数据。

打个比方：
- DDR5：单车道，但跑得快（频率高）
- HBM3：16 车道，就算跑得慢点，总吞吐也碾压

### 为什么 HBM 这么贵？

1. **3D 堆叠工艺复杂**：要把 8-12 层 DRAM 芯片堆在一起，层之间用硅通孔（TSV）穿透连接，良率极难控制
2. **封装成本高**：HBM 必须和 GPU 封装在同一块基板上，通过硅中介层（Interposer）互联，这需要 CoWoS（Chip-on-Wafer-on-Substrate）封装技术，目前产能严重不足
3. **容量限制**：每堆栈最多 24-36 GB，GB300 要达到 288 GB 需要 8 个堆栈同时工作

---

## 为什么不能像 DDR 那样随意加容量？

一个 GPU 核心周围的空间是固定的，能放的 HBM 堆栈数量有限：

| GPU | HBM 堆栈数 | 总显存 | 位宽 |
|-----|-----------|--------|------|
| A100 | 6 | 80 GB | 5,120 bit |
| H100 | 6 | 80 GB | 5,120 bit |
| B200 | 8 | 192 GB | 8,192 bit |
| **GB300** | **8+** | **288 GB** | **8,192 bit+** |

要增加容量，要么：
- 加更多 HBM 堆栈 → 但 GPU 芯片面积有限，CoWoS 封装成本飙升
- 用更高密度的 HBM → 每堆栈从 16 GB 到 24 GB 到 36 GB，良率逐步下降

这也是为什么 Blackwell 花了很大精力做 **NVLink 内存池化**——让 2 张 GPU 的显存合并为 1 个更大的逻辑显存。

## 🛠 实操指南

### 📋 决策指南：你需要多少显存？预算怎么分配？

**先算显存需求，再决定买哪代 GPU：**

```python
# 显存需求估算公式
模型参数量(B) × 精度字节 × (1 + 优化器系数 + 梯度系数) + 激活值

# 实际数字（2026 年典型场景）：
# 全量训练 70B（FP16）:
#   140 GB（参数）+ 280 GB（Adam 状态）+ 140 GB（梯度）+ ~70 GB（激活值）
#   = 630 GB → 需要 8×H100（80 GB × 8）
#
# LoRA 微调 70B（FP16）:
#   140 GB（参数）+ 少量 LoRA 权重 ≈ 150 GB
#   → 1×GB300（288 GB）就够了！
#
# 推理 70B（FP16）:
#   140 GB（参数）→ 2×H100 NVL（140 GB 对半分）
```

**2026 年每 GB 显存的成本对比：**

| GPU | 显存总容量 | 显存类型 | 显存成本占比 | 每 GB 成本（估算） |
|-----|-----------|---------|------------|-----------------|
| H100 SXM | 80 GB HBM3 | ~$1,200 | ~15% BOM | ~$15/GB |
| H200 SXM | 141 GB HBM3e | ~$2,100 | ~25% BOM | ~$15/GB |
| B200 | 192 GB HBM3e | ~$2,800-3,200 | **~45-63% BOM** | ~$15-17/GB |
| MI300X | 192 GB HBM3 | ~$1,600 | ~30% BOM | ~$8/GB |
| GB300 | 288 GB HBM3e | ~$4,000+ | **>50% BOM** | ~$14/GB |

**一条经验**：在 B200 上，显存成本已经超过了 GPU 芯片本身的成本。这意味着**未来 GPU 的价差主要来自显存大小，而不是算力**。

### 🔧 自己动手验：你的训练任务到底吃多少显存？

```bash
# 1. 最简单的检查：训练过程中看显存占用
nvidia-smi --query-gpu=name,memory.used,memory.total --format=csv -l 5
# 在训练启动后观察显存峰值（通常在前几个 step 达到）

# 2. 用 PyTorch 的 memory 统计定位谁在吃显存
python -c "
import torch

# 模拟一个 7B 模型
model = torch.nn.Linear(4096, 4096)
print(f'模型参数: {sum(p.numel() for p in model.parameters())/1e9:.2f}B')

# 查看显存分配
print(f'已分配: {torch.cuda.memory_allocated()/1024**3:.1f} GB')
print(f'缓存: {torch.cuda.memory_reserved()/1024**3:.1f} GB')
print(f'峰值: {torch.cuda.max_memory_allocated()/1024**3:.1f} GB')
"

# 3. 最精确：用 Nsight Systems 看显存分配
nsys profile --trace=cuda,nvtx python train.py
# 然后在 GUI 里看 Memory 时间线，找到峰值
```

### ⚠️ 常见误区

- **误区**："HBM 和 DDR 都是内存，HBM 贵只是因为 NVIDIA 想多赚钱"
  - **实际**：HBM 的制造工艺比 DDR 复杂得多——**3D 堆叠需要硅通孔（TSV）穿透 8-12 层 DRAM 芯片**，良率控制极其困难。2025 年 HBM3e 一度炒到 $17-20/GB，而同期 DDR5 只要 ~$5/GB。而且 HBM 需要和 GPU 通过 CoWoS 封装在一起，TSMC 的 CoWoS 产能 2025-2026 年一直处于**爆满状态**。

- **误区**："显存不够可以加，就像 DDR 内存条一样插几根"
  - **实际**：GPU 核心周围的空间是固定的，能放的 HBM 堆栈数量上限由**芯片面积和 CoWoS reticle 限制**决定。H100 最多 6 堆栈，B200 最多 8 堆栈。要在不增加堆栈数的情况下提升容量，只能靠每堆栈的密度（12-Hi → 16-Hi），而密度提升意味着良率下降、成本飙升。

- **误区**："显存越大的 GPU 性价比越高"
  - **实际**：2026 年 B200 的显存成本已占 BOM 的 45-63%，显存成了 GPU 最贵的部分。如果你不需要 192 GB（比如只做推理，140 GB 就够了），H200（141 GB）可能是更划算的选择。**不要为用不上的显存付费。**

### 💡 一句话记住

> **"HBM 不是普通的'内存条'——它是 12 层 DRAM 堆起来的 3D 摩天大楼，每层之间用针尖大小的孔穿透连接。这就是为什么它又快又贵又少。2026 年，买一张 B200 的钱里一半花在了显存上。"**
