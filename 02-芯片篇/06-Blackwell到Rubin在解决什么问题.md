# Q: 从 Blackwell 到 Rubin，NVIDIA 在解决什么问题？

## 为什么会有这个问题

2022 年 Hopper（H100）发布，2024 年 Blackwell（B200）发布，2024-2025 年 Blackwell Ultra（GB300/B300）跟进。按 NVIDIA 官方路线图（GTC 2025 公布）：**2026 年推出 Rubin，之后是 Rubin Ultra（2027），再往后是 Feynman（2028）**。短短几年，NVIDIA 连跨三代架构。

每一代都在回答同一个核心问题：**"怎么让大模型训练更快、更便宜？"**

## 三代架构的演进逻辑

### 一张表看清差距

（算力一律标注**稠密/稀疏**——稀疏是稠密的 2 倍；不确定或未发布的数字以官方为准）

| 规格 | H100 (2022) | B200 (2024-25) | GB300/B300 (2025-26) | Rubin (2026) |
|------|------------|------------|----------------|-------------|
| 架构 | Hopper | Blackwell | Blackwell Ultra | Vera Rubin |
| 晶体管 | 800 亿 | 2,080 亿 | 2,080 亿+ | 未公开 |
| 制程 | TSMC 4N | TSMC 4NP | TSMC 4NP | TSMC 3nm（NVIDIA 口径） |
| 显存 | 80 GB HBM3 | 192 GB HBM3e | **288 GB** HBM3e | HBM4（288 GB+，官方口径） |
| 显存带宽 | 3.35 TB/s | 8 TB/s | 8 TB/s | 约 13 TB/s（厂商口径） |
| 功耗（GPU TDP） | 700 W | ~1,000 W | **1,400 W** | ~1,800 W（厂商口径） |
| NVLink | 4.0（900 GB/s 双向） | 5.0（1,800 GB/s 双向） | 5.0（1,800 GB/s 双向） | 下一代（以官方发布为准） |
| FP8 算力 | **2.0 PFLOPS 稠密**（稀疏 4.0） | **4.5 PFLOPS 稠密**（稀疏 9） | 约 B200 的 1.1-1.2×（厂商口径） | 以官方发布为准 |
| FP4 算力 | 不支持 | **9 PFLOPS 稠密**（稀疏 18） | 约 B200 的 1.5×（厂商口径） | 相对 Blackwell 推理约 3.3×（厂商口径，随配置变化） |
| 网卡 | CX-7（400G/端口） | CX-8（800G/端口） | CX-8（800G/端口） | CX-9（**1.6T/端口，下一代**） |

> 注意两点：① **1.6T 不是 CX-8**——CX-8 是 800G/端口，1.6T 属于下一代 CX-9 级别；② 不给 Rubin 编造绝对 PFLOPS 数字，NVIDIA 官方给的是**相对上一代的倍数**，且随配置变化。

**核心趋势**：每一代都围绕这四个方向：
1. **更大显存**：让更大的模型能装进单卡，减少模型并行开销
2. **更高带宽**：HBM3e/HBM4 和 NVLink 带宽提升
3. **更低精度训练**：FP8 → FP4，在精度和速度间找到新平衡
4. **更高效扩展**：更大的 NVLink 域和更好的互联拓扑

## 按代详细看

### H100（Hopper）— 铺路的一代

H100 是第一个原生支持 **FP8 训练** 的 GPU（Compute Capability 9.0），引入了 Transformer Engine。它的意义在于验证了几个关键能力：
- FP8 训练可以达到接近 FP16 的精度
- 大规模集群（万卡级别）可以稳定运行
- NVLink + NVSwitch 3 方案成熟

### B200（Blackwell）— 双 die 合体

Blackwell 是两个 GPU die 通过 NVLink 合并为一个逻辑 GPU：

```
传统方案：                           Blackwell：
┌──────────────┐                  ┌────────┬────────┐
│  H100 die    │                   │ B200    │ B200   │
│  80 GB HBM   │                  │ Die #1  │ Die #2 │
│  FP8 2.0PF   │                  │ 96 GB   │ 96 GB  │
└──────────────┘                  │ FP4 4.5PF│ FP4 4.5PF│
                                  └────────┴────────┘
                                  通过 NVLink 5.0 桥接
                                  逻辑单卡：192 GB
                                  FP4 稠密 9 PFLOPS（稀疏 18）
                                  FP8 稠密 4.5 PFLOPS（稀疏 9）
```

**核心价值**：更大的显存意味着很多以前需要 TP（张量并行）的模型，现在单卡就能放了。这极大地简化了大规模训练的网络拓扑。

### GB300/B300（Blackwell Ultra）— 为超大集群优化

GB300/B300 不是简单的提频。它的核心变化：
- **288 GB HBM3e**，可以装下 70B 模型的完整 BF16 权重（140 GB）还剩大量空间
- **FP4 算力约为 B200 的 1.5×（厂商口径）**，专为低精度推理优化
- **CX-8 网卡 800G/端口**（1.6T 是下一代 CX-9），匹配万卡集群网络需求
- **NVL72 整柜必须液冷**（整柜约 132 kW；注意这是机柜密度问题，8 卡 DGX B300 整机约 14-15 kW 仍可风冷——见 [[07-功率越来越高散热怎么办]]）

**核心价值**：单卡能装下更大的模型；800G 网卡让机间通信不再是瓶颈。

### Rubin / Rubin Ultra — 官方路线图的下一站

按 GTC 2025 官方口径（厂商口径，随配置变化）：
- **Vera CPU**：自研 CPU，与 Rubin GPU 组成 Vera Rubin 平台（详细规格以官方发布为准）
- **Rubin GPU**：推理算力**相对 Blackwell 约 3.3×**（NVIDIA 官方相对口径；官方未给出可靠的绝对 FP8 PFLOPS，不要引用"约 100 PFLOPS"这类未经官方确认的数字）
- **NVLink 域扩展**：NVL144（Rubin）→ NVL576（Rubin Ultra）
- **训练 10T 参数模型**：NVIDIA 官方称 Rubin Ultra NVL576 训练 10T 参数模型的能耗为 GB200 NVL72 的约 1/4（厂商口径）
- **时间线**：**2026 年推出 Rubin 并逐步量产爬坡，Rubin Ultra 在 2027 年**。截至撰写时 Rubin 尚未大规模出货，把"Rubin 已经全面量产"当作事实是不准确的。

## 选型怎么落地

不预测具体出货占比（会随供应链变动），只给可操作的结论：

| 系列 | 状态 | 对采购者的意义 |
|------|------|------|
| **GB300/B300（Blackwell Ultra）** | 已量产，主力供货 | 当前大算力采购的主力选择 |
| **GB200/B200（Blackwell）** | 已量产，持续供货 | 软件栈成熟，生态最稳 |
| **H200/H100（Hopper）** | 存量主力 | 预算有限/微调场景仍然够用 |
| **Vera Rubin** | 2026 年推出/逐步量产 | 下一代，早期尝鲜有良率与软件适配风险 |

**行业结论**：Blackwell 系列（尤其是 GB300/B300）仍是当前 AI 训练的主力硬件；Rubin 的角色是"下一代规划"，不是"现在就能买到"。

## 🛠 实操指南

### 📋 决策指南：该买哪代 GPU？

| 你的需求 | 推荐选型 | 理由 |
|---------|---------|------|
| 微调 7B-70B，单节点能搞定 | **H100 / H200** | 成本低，供应充足，8×80GB=640GB 显存对大多数模型够用 |
| 预训练 70B+，需要极致算力 | **B200 / GB300** | 192-288 GB 单卡显存，很多模型不需要张量并行就能装下 |
| 长上下文训练（128K+） | **B200 / GB300** | 更大显存 = 更长的序列长度 |
| 推理部署，成本敏感 | **H200 / B200**（FP8 推理） | B200 FP8/FP4 推理吞吐明显高于 H100 |
| 国产化要求 | **昇腾 910C / 国产 IB 方案** | 华为昇腾 + 国产 IB 的组合正在成熟（[[05-为什么训练还是首选NVIDIA]]） |

**一条经验**：买当前的主力量产产品（Blackwell 系），意味着 NVIDIA 的驱动、NCCL、Megatron-Core 等软件栈主要针对它优化。**买主流产品 = 享受最佳软件支持。**

### 🔧 自己动手验：你的 GPU 是不是"假满载"？

```bash
# 检查 GPU 是否在节流（温度/功耗降频）
nvidia-smi -q -d TEMPERATURE
# Perf State 为 P0 = 满速，P1/P2 = 降频
# 如果频繁出现 P2 → 散热不足，考虑改善风道或液冷

# 检查 GPU 实际功耗
nvidia-smi -q -d POWER
# H100 满载应接近 700W，B200 应接近 1,000W，GB300/B300 应接近 1,400W
# 如果远低于 TDP → GPU 没有被充分利用
```

### ⚠️ 常见误区

- **误区**："买最新的 Rubin，三年不用换"
  - **实际**：Rubin 2026 年才推出并逐步量产，Rubin Ultra 更晚（2027，官方口径）。而且 Rubin 用 **HBM4 和 3nm 全新制程**，初代产品通常有良率和稳定性问题。**对于生产环境，买 Blackwell 系列（GB300/B300）更稳妥。**
- **误区**："FP8 训练精度不够，还是用 BF16 保险"
  - **实际**：FP8 训练（H100/Transformer Engine 起支持）已经在学术界和工业界被广泛验证，在合理缩放策略下精度损失很小、吞吐收益显著。**BF16 作为主力精度的时代正在被 FP8 部分取代**（混合精度仍是主流：FP8 算矩阵、BF16/FP32 保敏感部分）。
- **误区**："GPU 算力翻倍 = 训练速度翻倍"
  - **实际**：Amdahl 定律——通信开销占总时间的比例不随 GPU 算力提升而减少。算力翻倍但通信没变，端到端可能只提速一部分。**这就是为什么网络和存储增速必须和 GPU 算力增速匹配。**
- **误区**："引用绝对 PFLOPS 比较代际"
  - **实际**：比较算力必须**同一精度、同稠密/稀疏口径**。把 B200 的 FP8 稠密 4.5 PFLOPS 和别家的 FP4 稀疏数字放一起比，会差出好几倍。引用 Rubin 等未发布产品时，只用官方相对口径（"约 3.3×"，厂商口径），不要转发未确认的绝对数字。

## 对后续的铺垫

GPU 的进化一直在朝着同一个方向：**更强的单卡能力 + 更快的互联速度 + 更低的训练精度**。

但这同时也带来了一个能源层面的问题：**1,400 W 的单卡功耗，10 万张卡就是 140 MW 量级，相当于一座小型电厂的输出。**
