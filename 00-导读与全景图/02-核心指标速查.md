# Q: AI 集群有哪些核心指标？怎么看？

以下是在 AI 集群讨论中最常出现的指标。按「算力→通信→存储→效率」四个维度排列。

---

## 一、算力指标

### FLOPS（Floating Point Operations Per Second）

衡量计算速度的最核心指标。单位递进：

| 单位 | 含义 | 语境 |
|------|------|------|
| 1 TFLOPS | 10¹² FLOPS | 单卡性能 |
| 1 PFLOPS | 10¹⁵ FLOPS | 单节点性能 |
| 1 EFLOPS | 10¹⁸ FLOPS | 集群总性能 |
| 1 ZFLOPS | 10²¹ FLOPS | 下一代超算目标 |

**注意**：同样的 GPU，不同精度算力差异巨大。以 NVIDIA H100 SXM 为例（NVIDIA 官方把 TF32/BF16/FP16/FP8/INT8 全部标注为 "With sparsity"，所以下表同时给出稠密与稀疏两组值）：

| 精度 | 算力（稠密 / 稀疏，TFLOPS） | 用途 |
|------|------|------|
| FP64 | 34（张量核 67） | 科学计算（AI 基本不用） |
| FP32 | 67 | 传统深度学习 |
| TF32 | 494 / 989 | Tensor Core 默认 AI 精度 |
| **FP16/BF16** | **989 / 1,979** | **AI 训练主力精度** |
| FP8 | 1,979 / 3,958 | 新一代低精度训练 |
| FP4 | H100 不支持（Blackwell 起才有） | — |

所以看 FLOPS 一定要问一句：**什么精度？**

### TOPS（Tera Operations Per Second）

主要用在推理芯片的 INT8/INT4 算力描述。1 TOPS = 10¹² INT8 OPS。

## 二、通信指标

### 带宽（Bandwidth）

衡量数据传输速度。AI 集群中有三个层级的带宽：

| 层级 | 典型值（H100 SXM） | 技术 |
|------|-------------------|------|
| GPU 内部（HBM→Core） | 3.35 TB/s | HBM3/HBM3e |
| **卡间（GPU↔GPU）** | **900 GB/s**（双向） | **NVLink 4.0 + NVSwitch** |
| 机间（Server↔Server） | 400-800 Gb/s = 50-100 GB/s | InfiniBand NDR / RoCE |

**关键认知**：卡间带宽（900 GB/s）是机间带宽（100 GB/s）的 9 倍。这意味着**跨机通信天然比卡间通信慢一个数量级**。这就是为什么并行策略要把通信密集的操作留在 NVLink 域内（[[05-并行策略篇/01-数据并行DP]]）。

### 时延（Latency）

| 层级 | 典型值 |
|------|--------|
| GPU→HBM | ~0.1 μs |
| NVLink 卡间 | ~1 μs |
| 机间 InfiniBand | ~1.5 μs |
| 机间 RoCEv2 | ~2-3 μs |
| 跨洲通信 | 50-100 ms |

### Bisection Bandwidth（对分带宽）

**最重要的集群网络指标**。定义：把集群切成两个等大的半区，跨半区通信的最大带宽。

> **为什么重要**：All-Reduce 等集体通信的瓶颈通常不是单条链路，而是**最窄的横截面**。对分带宽直接决定了集群扩展时通信效率的上限。

### 对分带宽与算力之比

网络够不够快，可以用一个直白的比值来看：**集群总对分带宽（GB/s）÷ 集群总 AI 算力（TFLOPS）**。比值越高，每单位算力配到的跨半区带宽越充裕，网络越不容易成为瓶颈。

以本页第五节的 1,000 卡 H100 算例为例：对分带宽 ~12.8 Tb/s，换算成字节是 12,800 ÷ 8 = 1,600 GB/s；总 FP8 稠密算力为 1,979 TFLOPS。于是比值 = 1,600 ÷ 1,979 ≈ **0.8 GB/s 每 TFLOPS**——每 1 TFLOPS 算力配到约 0.8 GB/s 的跨半区带宽。

## 三、存储指标

### IOPS（Input/Output Operations Per Second）

主要影响**小文件读写**场景：数据加载时读取大量样本（数百到数千个小文件）。并行文件系统需要百万级 IOPS 才能喂饱 GPU。

### 吞吐量（Throughput）

顺序读写的速度，影响：
- **Checkpoint 保存**：几百 GB 的模型参数需要在几十秒内写完
- **大文件数据集加载**：预训练语料动辄 TB 级

理想值：聚合读吞吐 ≥ 训练数据消耗速度 × 2（留余量）。以 1,000 张 H100 训练为例，数据消耗约 20-40 GB/s，存储吞吐需 40-80 GB/s 起步。

### Checkpoint 带宽公式

```
checkpoint_size_bytes / target_seconds = required_write_throughput
```

一个 70B 模型 checkpoint（~140 GB）：

| 目标保存时间 | 所需写吞吐 | 可选方案 |
|------------|-----------|---------|
| 60 秒（宽松） | 2.3 GB/s | NFS 勉强 |
| 10 秒（合理） | 14 GB/s | 入门级并行文件系统 |
| **3 秒（理想）** | **47 GB/s** | **WEKA + GPU Direct Storage** |

## 四、效率指标

### MFU（Model FLOPs Utilization）

**最重要的 AI 训练效率指标**。定义：

```
MFU = 实际吞吐量 / 理论最大吞吐量
```

即：你花了这么多钱买的 GPU，实际用到了百分之几的理论算力？

| MFU 值 | 水平 | 典型场景 |
|--------|------|---------|
| 10-20% | 很差 | 没有任何优化的数据并行 |
| 25-35% | 一般 | 有基本的梯度累积和 AMP |
| 40-45% | 良好 | 有 3D 并行 + Profile 优化 |
| 45-50% | 优秀 | 精心优化的生产环境 |
| 50-55% | 顶级 | Megatron-Core + 极致调优；公开最佳实例为 MegaScale（12,288 张卡训 175B，55.2%） |

Meta 训练 Llama 3 405B 时，论文给出的是三种并行配置下的 MFU：8,192 卡时 43%、16,384 卡时 41%、131K 长上下文时 38%。

### GPU 利用率（nvidia-smi 报告的值）

**这个数字非常容易被误解**。`nvidia-smi` 报告的 GPU-Util 是"在过去的时间段内，有计算任务在运行的时间比例"，而不是"算力被使用了百分之几"。一个 GPU 可能在跑计算但远未达到峰值。所以：

- `nvidia-smi` 显示 100% ≠ GPU 满负荷工作
- 真正看算力利用要用 **Nsight Systems** 或 **DCGM** 采集的实际 Tensor Core 占用率
- 详见 [[08-运维观测篇/02-为什么GPU利用率100不一定好]]

### Model FLOPs/Byte（算术强度）

```
算术强度 = 总计算量 / 总访存量 (FLOPs/Byte)
```

这个比值决定了模型是**计算密集型**还是**访存密集型**：
- 比值高 → 瓶颈在计算 → 提升算力有效
- 比值低 → 瓶颈在访存 → 需要优化数据局部性

## 五、实际应用：一个集群的指标怎么算？

假设你要搭建一个 **1,000 卡 H100** 的训练集群：

| 指标 | 计算 | 结果 |
|------|------|------|
| 总 FP8 算力（稠密） | 1,000 × 1,979 TFLOPS | ≈ 1.98 EFLOPS |
| 总 FP16/BF16 算力（稠密） | 1,000 × 989 TFLOPS | ≈ 0.99 EFLOPS |
| 总显存 | 1,000 × 80 GB | 80 TB |
| NVLink 单机内带宽 | 8 卡 × 900 GB/s | 7.2 TB/s 机内 |
| NVLink 全集群带宽 | 125 机 × 7.2 TB/s | 900 TB/s |
| 机间网络总带宽 | 假设 8 台/架，每机 8×400G = 25.6 Tb/s | 25.6 Tb/s 架间 |
| 对分带宽 | 25.6 Tb/s ÷ 2（对半切） | ~12.8 Tb/s |
| 存储全闪吞吐量 | WEKA 群集 | ~100 GB/s+ |
| 目标 MFU | 经过调优 | 40-55% |
