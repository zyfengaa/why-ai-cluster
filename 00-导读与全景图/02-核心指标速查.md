# Q: AI 集群有哪些核心指标？怎么看？

以下是在 AI 集群讨论中最常出现的指标。按「算力→通信→存储→效率」四个维度排列。

---

## 一、算力指标

### FLOPS（Floating Point Operations Per Second）

衡量计算速度的最核心指标。单位递进：

| 单位 | 含义 | 语境 |
|------|------|------|
| 1 TFLOPS | 10¹² FLOPS | 单卡性能 |
| 1 PFLOPS | 10¹⁵ FLOPS | 单节点性能 |
| 1 EFLOPS | 10¹⁸ FLOPS | 集群总性能 |
| 1 ZFLOPS | 10²¹ FLOPS | 下一代超算目标 |

**注意**：同样的 GPU，不同精度算力差异巨大。以 NVIDIA H100 为例：

| 精度 | 算力（稠密 / 稀疏） | 用途 |
|------|---------------------|------|
| FP64 | 34 / — TFLOPS | 科学计算（AI 基本不用） |
| FP32 | 67 TFLOPS | 传统深度学习 |
| TF32 Tensor Core | 494 / 989 TFLOPS | 单精度训练加速 |
| **FP16/BF16 Tensor Core** | **989 / 1,979 TFLOPS** | **AI 训练主力精度** |
| FP8 Tensor Core | **1,979 / 3,958 TFLOPS** | 新一代低精度训练 |
| FP4 | H100 不支持 | —（Blackwell 起支持） |

所以看 FLOPS 一定要问两句：**什么精度？稠密还是稀疏？** 稀疏算力通常是稠密的 2×，不能直接用来算 MFU。

### TOPS（Tera Operations Per Second）

主要用在推理芯片的 INT8/INT4 算力描述。1 TOPS = 10¹² INT8 OPS。

## 二、通信指标

### 带宽（Bandwidth）

衡量数据传输速度。AI 集群中有三个层级的带宽：

| 层级 | 典型值（H100 SXM） | 技术 |
|------|-------------------|------|
| GPU 内部（HBM→Core） | 3.35 TB/s | HBM3/HBM3e |
| **卡间（GPU↔GPU）** | **900 GB/s**（双向） | **NVLink 4.0 + NVSwitch** |
| 机间（Server↔Server） | 400-800 Gb/s = 50-100 GB/s（单向） | InfiniBand NDR / XDR、RoCE |

**关键认知**：卡间带宽（900 GB/s）约为机间单端口带宽（50–100 GB/s）的 9–18 倍。这意味着**跨机通信天然比卡间通信慢一个数量级**。这就是为什么并行策略要把通信密集的操作留在 NVLink 域内（[[05-并行策略篇/01-数据并行DP]]）。

### 时延（Latency）

| 层级 | 典型值 |
|------|--------|
| GPU→HBM | ~0.3-0.5 μs |
| NVLink 卡间 | ~1 μs |
| 机间 InfiniBand | ~1.5 μs |
| 机间 RoCEv2 | ~2-3 μs |
| 跨洲通信 | 50-100 ms |

### Bisection Bandwidth（对分带宽）

**最重要的集群网络指标**。定义：把集群切成两个等大的半区，跨半区通信的最大带宽。

> **为什么重要**：All-Reduce 等集体通信的瓶颈通常不是单条链路，而是**最窄的横截面**。对分带宽直接决定了集群扩展时通信效率的上限。

### 对分带宽与算力比（Albedo）

经验法则：**集群的对分带宽（GB/s） ÷ 峰值算力（TFLOPS）≈ 1 字节/FLOP** 时，网络通常不会成为瓶颈。比值明显小于 1（如 0.1–0.3）时，大模型训练会更依赖拓扑、梯度累积和通信重叠。

> 注意单位：带宽用 GB/s（字节），算力用 TFLOPS（浮点运算/秒），比值单位是 Byte/FLOP。不要把 Tb/s 和 TFLOPS 直接相除。

## 三、存储指标

### IOPS（Input/Output Operations Per Second）

主要影响**小文件读写**场景：数据加载时读取大量样本（数百到数千个小文件）。元数据密集的并行文件系统通常需要十万到百万级 IOPS 才能避免元数据成为瓶颈。

### 吞吐量（Throughput）

顺序读写的速度，影响：
- **Checkpoint 保存**：几百 GB 的模型参数需要在几十秒内写完
- **大文件数据集加载**：预训练语料动辄 TB 级

理想值：聚合读吞吐 ≥ 训练数据消耗速度 × 2（留余量）。以 1,000 张 H100 训练为例，数据消耗约 20-40 GB/s，存储吞吐需 80-100 GB/s 起步。

### Checkpoint 带宽公式

```
checkpoint_size_bytes / target_seconds = required_write_throughput
```

一个 70B 模型 checkpoint：

- **仅 BF16 权重**：约 140 GB
- **可恢复训练的完整状态**（权重 + 梯度 + FP32 master + Adam m/v，约 16 B/参数）：约 **1.12 TB**
- 常见「模型 + 优化器」保存（约 14 B/参数）：约 **980 GB**

| 目标保存时间 | 所需写吞吐（按 980 GB） | 可选方案 |
|------------|------------------------|---------|
| 60 秒（宽松） | ~16 GB/s | 入门级并行文件系统 |
| 10 秒（合理） | ~98 GB/s | 中高端全闪并行文件系统 |
| **3 秒（理想）** | **~327 GB/s** | **多套 WEKA/并行 FS + GPU Direct Storage** |

## 四、效率指标

### MFU（Model FLOPs Utilization）

**最重要的 AI 训练效率指标**。定义：

```
MFU = 实际吞吐量 / 理论最大吞吐量
```

即：你花了这么多钱买的 GPU，实际用到了百分之几的理论算力？

| MFU 值 | 水平 | 典型场景 |
|--------|------|---------|
| 10-20% | 很差 | 没有任何优化的数据并行 |
| 25-35% | 一般 | 有基本的梯度累积和 AMP |
| 40-50% | 良好 | 有 3D 并行 + Profile 优化 |
| 50-65% | 优秀 | 精心优化的生产环境 |
| 70%+ | 顶级 | Megatron-Core + 极致调优 |

Meta 公开报告 Llama 3 405B 的 MFU 为 **38–43%**（不同并行配置与训练阶段），不是同一套配置「优化前 38%、优化后 43%」。

### GPU 利用率（nvidia-smi 报告的值）

**这个数字非常容易被误解**。`nvidia-smi` 报告的 GPU-Util 是「采样期内**至少有一个 kernel 在执行**的时间比例」，不是「CUDA Core 被使用了百分之几」，也不是算力利用率。一个 GPU 可能一直有 kernel 在跑（例如 NCCL 自旋等待），但实际计算吞吐很低。所以：

- `nvidia-smi` 显示 100% ≠ GPU 满负荷工作
- DCGM 的 `DCGM_FI_PROF_SM_ACTIVE` 是更好的代理指标（0–1 比例），但它衡量的是 warp 驻留，仍不等于有效算力
- 真正定位瓶颈要用 **Nsight Systems**（时间线）和 **Nsight Compute**（kernel 级）
- 详见 [[08-运维观测篇/02-为什么GPU利用率100不一定好]]

### Model Bytes/FLOPS Ratio（算术强度）

```
算术强度 = 总计算量 / 总访存量 (Bytes/FLOP)
```

这个比值决定了模型是**计算密集型**还是**访存密集型**：
- 比值高 → 瓶颈在计算 → 提升算力有效
- 比值低 → 瓶颈在访存 → 需要优化数据局部性

## 五、实际应用：一个集群的指标怎么算？

假设你要搭建一个 **1,000 卡 H100** 的训练集群：

| 指标 | 计算 | 结果 |
|------|------|------|
| 总 FP8 稠密算力 | 1,000 × 1.979 PFLOPS | ~2 EFLOPS |
| 总 FP16/BF16 稠密算力 | 1,000 × 0.989 PFLOPS | ~1 EFLOPS |
| 总显存 | 1,000 × 80 GB | 80 TB |
| NVLink 机内带宽 | 125 台 × 900 GB/s | 112.5 TB/s（聚合） |
| 机间网络总带宽 | 125 台 × 8×400G = 125 × 3.2 Tb/s | 400 Tb/s（聚合） |
| 每机架上行带宽 | 8 台/架 × 3.2 Tb/s | **25.6 Tb/s/架** |
| 对分带宽（1:1 非阻塞） | 400 Tb/s ÷ 2 | ~200 Tb/s |
| 存储全闪吞吐量 | WEKA 群集 | ~100 GB/s+ |
| 目标 MFU | 经过调优 | 40–55%（405B 公开值 38–43%） |
