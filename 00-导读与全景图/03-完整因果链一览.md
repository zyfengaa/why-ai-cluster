# Q: AI 集群的完整发展逻辑是什么？

本教程认为：**每一项技术都不是凭空冒出来的，而是为了解决前一项技术捅出的新问题。**

下面用一张长图浓缩整条因果链。每个→代表"引出了新的问题"，每个←代表"为了解决这个问题，诞生了……"。

---

## 核心因果链

```
┌─────────────────────────────────────────────────────────────┐
│  第1步：模型越来越大了                                        │
│  GPT-3 (175B, 2020) → Llama 3 (405B, 2024) → GPT-4 传闻 1.8T │
│  单卡 80GB HBM 根本放不下                                      │
└─────────────────────────────┬───────────────────────────────┘
                              │
                              ▼
  ┌───────────────────────────────────────────────────────────────┐
  │  第2步：数据并行（DP）诞生                                    │
  │  把模型复制到多张卡上，每张卡处理不同的batch，梯度做同步       │
  │  解决了：单卡放不下 → 多卡分散                                │
  │  带来了新问题：梯度同步需要跨卡通信，通信成了瓶颈              │
  │  → 详细看 [[05-并行策略篇/01-数据并行DP]]                      │
  └─────────────────────────────┬───────────────────────────────┘
                                │
                                ▼
  ┌───────────────────────────────────────────────────────────────┐
  │  第3步：NVLink 和 NVSwitch                                   │
  │  PCIe 带宽太低（A100 × PCIe 4.0 = 64 GB/s ↔ HBM 2 TB/s）     │
  │  NVLink 把卡间通信带宽提升 10 倍（900 GB/s）                  │
  │  NVSwitch 让 8 卡以上可以全互联                                │
  │  解决了：单机内卡间通信瓶颈                                    │
  │  带来了新问题：扩展到多机时，机间还是得走网络                   │
  │  → 详细看 [[02-芯片篇/02-PCIe瓶颈与NVLink诞生]]               │
  └─────────────────────────────┬───────────────────────────────┘
                                │
                                ▼
  ┌───────────────────────────────────────────────────────────────┐
  │  第4步：InfiniBand / RoCE 网络                               │
  │  多机之间需要快速可靠的 RDMA 通信                              │
  │  InfiniBand：硬件无损、芯片级流控、确定性低延迟                  │
  │  RoCEv2：跑在标准以太网上、成本低、生态开放                      │
  │  UEC 1.0（2025）：彻底重写以太网协议栈，挑战 IB                │
  │  解决了：跨机通信                                            │
  │  带来了新问题：网络拓扑怎么设计才能最大化对分带宽？               │
  │  → 详细看 [[03-网络篇/*]]                                     │
  └─────────────────────────────┬───────────────────────────────┘
                                │
                                ▼
  ┌───────────────────────────────────────────────────────────────┐
  │  第5步：张量并行（TP）和流水线并行（PP）                       │
  │  模型太大，单卡显存装不下整个模型怎么办？                        │
  │  TP：把一层切成多份，分别放在不同卡上                           │
  │  PP：把不同层分到不同卡上，流水线执行                           │
  │  ZeRO：不切模型，但去掉冗余数据分片存                          │
  │  解决了：模型显存放不下                                        │
  │  带来了新问题：3D并行组合后通信模式极其复杂                      │
  │  → 详细看 [[05-并行策略篇/*]]                                  │
  └─────────────────────────────┬───────────────────────────────┘
                                │
                                ▼
  ┌───────────────────────────────────────────────────────────────┐
  │  第6步：训练框架封装复杂度                                     │
  │  DeepSpeed（微软）：ZeRO-1/2/3 自动分片                       │
  │  Megatron-Core（NVIDIA）：TP+PP+DP 工业级实现                  │
  │  FSDP2（Meta/PyTorch）：2026 年微调默认选择                    │
  │  解决了：工程师不需要手动实现并行逻辑                           │
  │  带来了新问题：这么多框架怎么选？混精度怎么搞？                   │

  └─────────────────────────────┬───────────────────────────────┘
                                │
                                ▼
  ┌───────────────────────────────────────────────────────────────┐

  │  并行文件系统（Lustre/WEKA/GPFS）：多机并行读写                │
  │  GPU Direct Storage：NVMe → GPU HBM 直通，绕过 CPU             │
  │  解决了：数据加载成为瓶颈                                      │
  │  带来了新问题：存储选型复杂，成本高                             │
```

## 一个比喻：AI 集群就像一支交响乐团

| 角色 | 对应技术 | 问题 |
|------|---------|------|
| 首席小提琴（领奏） | GPU | 算力核心 |
| 乐谱架之间的传谱 | NVLink | 卡间通信 |
| 不同声部之间的配合 | All-Reduce | 梯度同步 |
| 指挥 | 调度器（Slurm/K8s） | 资源分配 |
| 乐谱库 | 并行文件系统 | 数据存储 |
| 调音师 | NCCL 调优 | 网络参数优化 |
| 录音回放检查 | Profiling 工具 | 性能分析 |

任何一个环节出问题，整首曲子（训练任务）都会受影响。
