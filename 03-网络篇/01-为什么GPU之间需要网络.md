# Q: 为什么 GPU 之间需要网络？

## 为什么会有这个问题

NVLink 很强，但 NVLink 线缆最长只能到 ~0.5 米（机箱内部）。当集群从 8 卡扩展到 64 卡、1,000 卡时，你**必须通过服务器间的网络来传输数据**。

这里有一个很多人都忽视的问题：**NVLink 虽然带宽高达 900 GB/s（双向），但它只覆盖了机箱内的通信。** 一旦扩展到多机，跨机 All-Reduce、梯度同步、参数广播——全部要走网络。

### 规模的决定性

来看一个真实的集群架构。xAI 在 2024 年建成的 Colossus 训练集群（用于训练 Grok 系列）——**起步约 10 万张 H100，后扩至约 20 万张 H100/H200 混合**——它的后端网络是这样的：

```
每个计算节点：8 张 H100/H200
每个机架：8 台服务器 = 64 GPU
每台服务器：8×BlueField-3 SuperNIC + 1×ConnectX-7 网卡
          = 9 × 400G = 3.6 Tb/s 网络带宽/服务器
后端网络：NVIDIA Spectrum-X 以太网（三层 Clos，不是 InfiniBand）
规模：2024 年建成约 100K H100，随后扩至约 200K H100/H200

这只是一个例子。更常见的 1,000 卡集群会是这样：
```

| 集群规模 | GPU 数 | 服务器数（8卡/台） | 网络端口数 |
|---------|--------|-----------------|-----------|
| 小规模 | 8 | 1 | 仅 NVLink |
| 中等规模 | 64 | 8 | 64 × 400G |
| **典型大模型项目** | **1,024** | **128** | **1,024 × 400G** |
| Meta Llama 3 | 24,576 × 2 套（一套 RoCEv2、一套 IB NDR） | 3,072 × 2 | 24,576 × 400G × 2 套 |
| xAI Colossus | 约 200,000（H100/H200） | 约 25,000 | 每服务器 9 × 400G |

**一个 1,024 卡的网络后端就需要超过 1,000 个 400G 端口**。每一个端口、每一根光模块、每一台交换机，都要精心选型。

## 跨机通信的核心场景

### 场景 1：All-Reduce（梯度同步）— 最高频、最敏感的通信

这是 AI 集群中最重要的通信模式。来看一个具体的时间线：

```
时间线（每次训练迭代，单位：毫秒）：

0 ms      50 ms     100 ms    150 ms    200 ms
├──────────┼──────────┼──────────┼──────────┤
███████████████████░░░░░░░░░░░░░░░░░░░░░░░░
│  前向传播（50ms）   │  反向传播（100ms）   │
                      └────────── All-Reduce 梯度同步（50ms）
```

**本章统一假设**：Llama 3 70B、1,024 卡全分片训练、每步 200 ms → **每秒 5 步（5 step/s）**。下面所有推导都用这个值。

以 Llama 3 70B 训练为例：
- 70B 模型 BF16 梯度共 ~140 GB；全分片后每卡负责 ~1/1,024 ≈ 137 MB 的梯度分片
- Ring All-Reduce 每卡收发约 2×137 MB ≈ 280 MB（每卡通信量与集群规模基本无关）
- 1,024 卡**聚合流量** ≈ 1,024 × 280 MB ≈ **280 GB/步**
- 每秒 5 步 → 聚合网络流量 **≈ 1.4 TB/s**

如果一次 All-Reduce 因为网络抖动从 50 ms 变成 150 ms，单步时间从 200 ms 变成 300 ms，MFU 直接跌去约 33%。

### 场景 2：Checkpoint 保存 — 低频但毁灭性的写风暴

训练一个 70B 模型，先分清三个数（BF16 权重按 2 B/参数，完整训练状态按 16 B/参数）：

```
仅模型权重：140 GB（70B × 2 bytes）
权重 + 优化器状态（Adam m/v + FP32 master，14 B/参数）：约 980 GB
完整训练状态（权重 + 梯度 + 优化器，16 B/参数）：约 1.12 TB

Checkpoint 通常写"权重 + 优化器状态" ≈ 980 GB（本节按此口径计算）

1,024 卡集群每 45 分钟保存一次：
  一天 32 次 Checkpoint
  一天写入总量：约 31.4 TB
  每次 Checkpoint 写时间 = GPU 闲置时间

要在 30 秒内写完：需要约 32.7 GB/s 的聚合存储写带宽
如果只有 3.3 GB/s：每次要写 5 分钟
```

如果带宽不够，每次 Checkpoint 需要 5 分钟 vs 30 秒，一天就多浪费 **2.4 小时**的千卡算力。按 H100 每小时 $3.5 算，一天烧掉 **$8,600**。

### 场景 3：数据加载 — 喂不饱的 GPU

训练时 CPU 负责读取训练数据、做预处理，然后送给 GPU。数据量看一个真实的吞吐需求（沿用上面的统一假设：每卡每步 4 个样本、8,192 tokens、5 步/秒）：

```
每张 GPU 的数据消耗：
  每步 = 4 × 8,192 × 2 bytes = 65,536 bytes
  5 步/秒 → 约 320 KB/s（单卡，仅 token 读取口径）
  1,024 卡聚合 ≈ 335 MB/s

注意口径：上面是"单卡样本读取"的口径，
而下面说的"30+ GB/s"是存储系统"聚合吞吐"的口径，两者不是一回事。

所以问题不在于"每秒要读多少 token"，而在于：
  - 原始数据集可能是 10-100 TB（预训练语料）
  - 实际数据需要先加载、解压、tokenize、shuffle、batch
  - 数据预处理不仅需要带宽，还需要 CPU 算力
  - shuffle、多 epoch、样本读取放大都会成倍抬高真实需求
  - 存储系统必须留出峰值余量

所以存储系统要按"持续 30+ GB/s 聚合吞吐"来设计，
而不是按 335 MB/s 的"净 token 速率"来设计。
```

## AI 训练对网络的极端要求

为什么普通数据中心网络不行？看一个真实对比：

| 要求 | 普通数据中心 | AI 训练集群 | 差距原因 |
|------|------------|------------|---------|
| 带宽 | 10-100 Gb/s 每服务器 | **400 Gb/s–3.6 Tb/s 每服务器**（如 xAI 每服务器 9×400G） | GPU 通信量是普通服务的百倍 |
| 延迟容忍 | 1-10 ms | **< 2 μs** | 每次迭代都在同步，延迟直接积少成多 |
| 丢包容忍 | 可重传（TCP 设计如此） | **零容忍** | 一个丢包拖住 1,024 张卡等重传 |
| 流量模式 | 随机、疏密不均 | **周期性 All-Reduce 风暴** | 所有节点同时发请求，同时静默 |
| 可靠性 | 99.9% 链路可用 | **99.9999%** | 0.1% 的故障在万卡上 = 10 张卡永远掉线 |

**把网络稳定性换算成钱**：某 1,200 卡 RoCE 集群因 PFC 风暴平均每 3 天训练崩溃一次，每次恢复耗时 30-90 分钟。算一笔账（按 $3.5/GPU-h）：

```
一个月约 10 次崩溃 × 平均 1 小时恢复 = 12,000 GPU 小时
≈ 1.4 GPU 年 ≈ $42,000 直接损失

看起来"不多"？再看两个口径：
  1,200 卡满跑一个月 = 1,200 × 30 × 24 = 864,000 GPU 小时
                     ≈ 98.6 GPU 年 ≈ $302 万
  所以网络问题每拉低 1% 的有效算力，就是约 $3 万/月

（顺带辟个谣：网上流传"1,200 卡跑一个月损失 400+ GPU 年"
 在数学上不成立——1,200 卡一个月最多 98.6 GPU 年；
 要凑出 400 GPU 年得是 4,900 卡整月全损，按 $3.5/GPU-h 约值 $1,227 万。）

崩溃的真正代价不在停机本身，而在恢复后的掉队重算、
checkpoint 回退和工程师排错时间。
```

## 真实案例：Meta 的 Llama 3 网络怎么搭

Meta 在 2024 年公开了 Llama 3 训练的基础设施。注意：**不是一套 49,152 GPU 的大集群，而是两套 24,576 GPU 集群**：

```
集群规模：两套 24,576 H100（各 3,072 台服务器）
网络方案：一套 RoCEv2 以太网，一套 InfiniBand NDR
Llama 3 405B 实际在 16,384 GPU 上训练

RoCE 集群的三层 Fat-Tree 设计：
  T0–T1 收敛比 2:1，T1–T2 收敛比 7:1
  计算内网：400G RoCE
  存储网络：与计算网络分离
  管理网络：100G 标准以太网

结果（Meta 论文口径）：
  - 405B 训练 MFU 达到 38-43%
  - 但为跑通 RoCE，Meta 投入了大量网络调优与联合排错
  - 54 天训练期间发生 419 次意外中断（约 7.8 次/天），
    其中约 78% 归因于硬件问题

为什么 Meta 敢用 RoCE？
  - Meta 拥有全球最大的数据中心网络团队之一
  - 有自研集合通信库和深度调优能力
  - 以太网供应链与成本考虑
```

这个故事的关键教训：**Meta 能把万卡 RoCE 跑到 38-43% MFU，靠的是顶级网络团队数月的调优；没有这个能力的团队，IB 这类"开箱即用"的方案（或 Spectrum-X 这类自带逐包自适应路由的以太网）往往是更省心的选择。**

## 🛠 实操指南

### 📋 决策指南：你在什么规模需要开始操心网络？

| 你的集群规模 | 你应该关心的事 | 行动建议 |
|------------|--------------|---------|
| 1 台机器（8 GPU） | 几乎不需要操心网络 | 全在 NVLink 域内，Checkpoint 写本地盘 |
| 2-4 台（16-32 GPU） | 需要了解你的网络方案 | 确认网卡类型、交换机型号、链路带宽 |
| 16+ 台（128+ GPU） | **必须专业设计网络** | 找有经验的人做网络规划，不要自己搭 |
| 128+ 台（1,024+ GPU） | 网络决定训练成败 | 优先选成熟方案（IB / 调优好的 RoCE / Spectrum-X），并请专人做网络规划 |

### 🔧 自己动手验：你的网络够不够快？

在你的集群上跑一下 NCCL 带宽测试：

```bash
# 单机内测（确认 NVLink 正常）
mpirun -np 8 all_reduce_perf -b 128M -e 256M -f 2

# 跨机测（确认网络正常，N 为总 GPU 数）
mpirun -np N --hostfile hosts all_reduce_perf -b 256M -e 512M -f 2
```

**期望结果速查**（nccl-tests 的 busbw 是**每卡**口径，注意别和整机聚合带宽搞混）：

| 配置 | 期望 busbw（每卡） | 如果更低说明 |
|------|-----------------|------------|
| 8×H100 NVLink 单机 | > 400 GB/s | GPU/NVLink 可能有问题 |
| 2 节点 16×H100 + IB NDR400 | ~40-50 GB/s（受 400G 单端口 50 GB/s 单向限制） | 检查 GDR 是否启用 |
| 2 节点 16×H100 + RoCEv2 400G | ~40-48 GB/s（调优后） | 需要开始调优 |
| 2 节点 16×H100 + 以太网 TCP | 明显更低（协议栈开销大，多网卡难以聚合） | **严重问题，必须上 RDMA** |

> **注意**：`all_reduce_perf` 是 NCCL-tests 套件中的工具，你可以在 [GitHub - NVIDIA/nccl-tests](https://github.com/NVIDIA/nccl-tests) 找到源码，编译后在集群上运行。这是任何 AI 集群上线的**第一道测试**。

### ⚠️ 常见误区

- **误区**："我的网络是 400G，带宽肯定够"
  - **实际**："400G"是网卡单端口物理速率，实际有效带宽受限于协议、交换机背板、对分带宽、拥塞控制。未调优的 RoCE 可能只能用到 60% 的带宽。
- **误区**："网络延迟 1ms，这么小的影响可以忽略"
  - **实际**：AI 训练每次迭代同步一次。按本章统一假设（每步 200 ms = 5 步/秒），1 ms 额外延迟 × 5 步/秒 × 30 天 = **12,960 秒 ≈ 3.6 小时**的纯等待浪费——这还只是单次 1 ms 的情况。

### 📊 底线数字速查

| 指标 | 优秀 | 及格 | 报警 |
|------|------|------|------|
| 超订阅比（叶层下行带宽 : 对分带宽） | 1:1 | 2:1 | ≥ 4:1 |
| NCCL All-Reduce 带宽利用率 | > 90% | 70-90% | < 70% |
| 跨机 All-Reduce 延迟抖动 | < 5% | 5-15% | > 15% |
| 网络故障导致训练中断频率 | 0/月 | < 1/月 | > 1/月 |

> **关于"对分带宽/算力比"**：业界常用通信/算力比来衡量网络是否配得上算力，但要注意量纲——对分带宽用 **GB/s**，算力用 **TFLOPS**，两者相除的单位是 **Byte/FLOP**。例：1:1 无收敛的 1,024×H100 集群，对分带宽 ≈ 25,600 GB/s，总峰值算力 ≈ 1,012,000 TFLOPS（1,024 × 989），比值 ≈ 0.025 Byte/FLOP。**不能直接把 Gb/s 和 TFLOPS 相除**——那是两个不同量纲的数，除出来的结果没有物理意义。

### 💡 一句话记住

> **"AI 集群的网络不是'能通就行'，它决定了你几千万买的 GPU 能用出几分力。"**

## 回到根本问题

网络不是什么"能用就行"的东西。在 AI 集群中，网络直接决定了：
- 你的 MFU 能跑多高（通信占比过高会直接吃掉算力）
- 你的训练能多稳定（网络抖动 = 训练中断的风险）
- 你的团队要多累（IB 免调优 vs RoCE 持续调优，运维工作量差距很大）

这引出了两个关键技术的选择：**InfiniBand vs RoCEv2**。
